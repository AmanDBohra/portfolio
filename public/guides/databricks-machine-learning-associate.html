Databricks Certified Machine Learning Associate — Study Guide

Core machine learning on Databricks: the ML workflow (prep, train/validate, evaluate), Databricks ML tools (AutoML, Feature Store, MLflow tracking & registry, Model Serving), Spark ML for scaling, and hyperparameter tuning with Hyperopt.

~45 multiple-choice questions · 90 minutes · passing ~70% · Databricks ML tooling + practical ML concepts.

What it is

The Databricks Certified Machine Learning Associate validates the ability to build machine learning solutions on Databricks. It covers the ML workflow (data prep, train/validate, evaluate), the Databricks ML toolset (AutoML, Feature Store, MLflow tracking and registry, Model Serving), scaling with Spark ML, and hyperparameter tuning with Hyperopt.

It is the entry-level ML credential in the Databricks track, proving you can go from a dataset to a tracked, registered, and servable model using the platform's managed tools — bridging data engineering and applied machine learning.

Where it's used

  • Roles: Machine Learning Engineer, Data Scientist, Analytics Engineer moving into ML, or a data engineer supporting ML pipelines.
  • On the job: preparing features, training and tuning models, tracking experiments in MLflow, registering models, and scaling training/inference with Spark.
  • Career value: a strong signal of applied ML capability on the modern Lakehouse; a natural next step after the data-engineering certifications.
  • For this portfolio: extends the data-science and advanced-analytics work — turning models into governed, business-facing solutions.

In plain English

  • MLflow is a lab notebook that automatically records every experiment — what settings you used and how well it did — so you can compare and reproduce them later.
  • The Model Registry is a library with 'editions': you check a model into Staging, then Production, and apps just ask for 'the Production copy' without caring about version numbers.
  • Feature Store is a shared pantry of prepared ingredients (features). Everyone cooks with the same ingredients at training and serving time, so the dish tastes the same — no 'train-serve skew'.
  • Overfitting is memorizing the textbook instead of learning the subject: perfect on practice questions, lost on the real exam. Regularization and more data are the cure.
  • Hyperopt is an assistant that tries many settings for you and homes in on the best, instead of you guessing by hand.

Exam shortcut tricks

  1. Fit preprocessing (scalers/encoders/imputers) on TRAIN only — put them in a Pipeline so cross-validation does this per fold. 'Fit on all data' = leakage = a trap answer.
  2. Load the Production model by stage: models:/name/Production — not by a version number.
  3. For imbalanced classes, accuracy lies — use F1 or PR/ROC-AUC. RMSE/MAE/R² are regression only.
  4. Hyperopt: objective returns {'loss': ...}. Higher-is-better metric? Return its NEGATIVE. SparkTrials = many single-node models in parallel; plain Trials = already-distributed Spark ML models.
  5. StringIndexer → OneHotEncoder → (scale) → VectorAssembler → model. Assemble LAST; VectorAssembler errors on nulls, so impute first.
  6. Trees are scale-invariant; distance/gradient models (logistic/linear, kNN, SVM) need scaling.
  7. AutoML is 'glass-box' — it gives editable notebooks and logs every trial to MLflow, so it's reproducible.

Study roadmap

  1. ML fundamentals — supervised vs unsupervised, train/validation/test split, cross-validation, bias-variance, over/underfitting.
  2. Data prep & features — imputation, encoding (one-hot/string indexing), scaling, train-test leakage, Feature Store basics.
  3. MLflow tracking — runs, params/metrics/artifacts, autolog, model signatures, comparing experiments.
  4. AutoML — generating baseline models and the editable best-model notebook.
  5. Model registry — registering models, stages (Staging/Production), and loading by stage.
  6. Spark ML — MLlib estimators/transformers, Pipelines, pandas API on Spark, and pandas/Iterator UDFs for scaling inference.
  7. Hyperparameter tuning — Hyperopt (fmin, search spaces, SparkTrials) and cross-validation.
  8. Evaluation & deployment — metrics (accuracy/F1/AUC/RMSE), and batch/real-time serving basics.

Study notes

MLflow

  • Tracking logs params, metrics, artifacts, and models per run; mlflow.autolog() captures these automatically for many libraries.
  • A model signature records input/output schema; log with an input_example for validation.
  • Model Registry manages versions and stages (None/Staging/Production/Archived); load with models:/name/Production.

AutoML & Feature Store

  • AutoML trains many models and produces a leaderboard plus an editable notebook for the best model (glass-box).
  • Feature Store stores curated feature tables for reuse and consistent training/inference (avoids train-serve skew); use feature lookups.

Spark ML & scaling

  • MLlib uses Transformers (transform) and Estimators (fit → Model); chain them in a Pipeline.
  • pandas API on Spark scales pandas code; pandas UDFs / applyInPandas run vectorized Python at scale.
  • Use VectorAssembler to combine feature columns into a single features vector for MLlib.

Tuning & validation

  • Cross-validation reduces variance in the performance estimate; CrossValidator in Spark ML.
  • Hyperopt: define a search space, an objective returning loss, and run fmin (TPE); SparkTrials parallelizes single-node models across the cluster.
  • Avoid leakage: fit scalers/encoders on training data only (inside the Pipeline).

Hands-on projects

1. Claim-cost regression with a Spark ML pipeline

Goal: Predict insurance claim cost with a reproducible, leakage-free Spark ML pipeline.

Architecture & data model: Delta training data → Spark ML Pipeline (impute → index/encode → assemble → GBT/RF regressor) → CrossValidator tuning → test evaluation → MLflow-logged model.

Concepts covered:

  • Spark ML Pipeline: Chains preprocessing transformers and the final estimator so fit/transform apply consistently and without leakage.
  • Imputer / StringIndexer / OneHotEncoder / VectorAssembler: Impute nulls, index+encode categoricals, and assemble all features into the single vector MLlib expects.
  • Train/test split: randomSplit with a fixed seed creates reproducible train and held-out test sets.
  • CrossValidator: Averages performance across k folds over a ParamGrid to select robust hyperparameters.
  • RegressionEvaluator (RMSE): Scores regression error in the target's units on the test set.

Implementation steps:

  1. Assemble the Pipeline stages ending in the regressor.
  2. randomSplit(seed) then CrossValidator + ParamGridBuilder to tune.
  3. Evaluate RMSE/MAE/R² on the test set.
  4. Log the run and best model to MLflow.

Outcomes:

  • A reproducible, leakage-free claim-cost model.
  • Tuned hyperparameters via CV.
  • Tracked, comparable runs.

Stack: Spark ML (MLlib), MLflow, Delta

Directly extends predictive/insurance analytics into a governed Lakehouse ML workflow.

4. Hyperparameter tuning with Hyperopt

Goal: Systematically tune a model to minimize validation loss.

Architecture & data model: Search space → objective (train+CV, return loss) → fmin (TPE) with SparkTrials → best params → MLflow.

Concepts covered:

  • Hyperopt (fmin, search space): Optimizes hyperparameters by minimizing an objective over a defined space.
  • hp.loguniform / hp.choice: Log-scale sampling for rates/regularization; categorical choices for discrete options.
  • SparkTrials vs Trials: SparkTrials parallelizes single-node trials; Trials for already-distributed Spark ML.
  • Objective (STATUS_OK, loss): Return {'loss', 'status'}; negate higher-is-better metrics.
  • Cross-validation: Evaluate each trial with CV for a stable estimate.

Implementation steps:

  1. Define the search space (loguniform for LR/reg).
  2. Write the objective returning loss/status.
  3. Run fmin with max_evals and SparkTrials.
  4. Log the best params/metrics.

Outcomes:

  • Systematically optimized hyperparameters.
  • Parallelized, efficient search.
  • Reproducible tuning record.

Stack: Hyperopt, MLflow, Spark

Practice questions (100)

1. What does mlflow.autolog() do?

  • A. Deploys the model
  • B. Automatically logs params, metrics, and models for supported libraries ✓
  • C. Registers the model to Production
  • D. Creates a Feature Store table

Explanation: autolog() automatically captures parameters, metrics, artifacts, and the model for supported frameworks (scikit-learn, Spark ML, XGBoost, etc.), reducing manual logging.

2. In the MLflow Model Registry, how do you load the current Production model?

  • A. mlflow.load('latest')
  • B. models:/model_name/Production ✓
  • C. runs:/Production
  • D. dbfs:/Production

Explanation: The registry URI models:/<name>/<stage> (e.g., .../Production) loads whichever version is currently in that stage, decoupling consumers from specific version numbers.

3. What is the main benefit of Databricks Feature Store?

  • A. Faster notebooks
  • B. Reusable, governed feature tables that keep training and inference consistent (avoid train-serve skew) ✓
  • C. Automatic hyperparameter tuning
  • D. Model serving only

Explanation: Feature Store centralizes curated features so the same definitions are used at training and inference, preventing train-serve skew, and enables reuse and lineage.

4. Databricks AutoML produces which useful artifact besides a leaderboard?

  • A. A locked black-box model
  • B. An editable notebook for the best model (glass-box) ✓
  • C. A dashboard only
  • D. A Feature Store table

Explanation: AutoML is 'glass-box': it generates editable notebooks (including for the best model) so you can inspect and refine the generated code rather than getting an opaque model.

5. Why fit imputers/encoders on the training set only (e.g., inside a Pipeline)?

  • A. To save memory
  • B. To prevent data leakage from validation/test into training ✓
  • C. To speed up fitting
  • D. It is not required

Explanation: Fitting preprocessing on all data leaks information from validation/test into the model, inflating performance estimates. Fit on train only (Pipelines apply this correctly per fold).

6. In Spark ML, what is the difference between a Transformer and an Estimator?

  • A. They are the same
  • B. A Transformer has transform(); an Estimator has fit() that returns a Model (a Transformer) ✓
  • C. Estimators only work on streaming
  • D. Transformers train models

Explanation: Transformers implement transform() (e.g., VectorAssembler). Estimators implement fit() which learns and returns a Model (itself a Transformer), e.g., LogisticRegression → LogisticRegressionModel.

7. Which Spark ML step combines multiple feature columns into one vector column for MLlib?

  • A. StringIndexer
  • B. VectorAssembler ✓
  • C. StandardScaler
  • D. OneHotEncoder

Explanation: VectorAssembler merges specified columns into a single 'features' vector column, which MLlib estimators expect as input.

8. What is cross-validation used for?

  • A. Deploying models
  • B. Estimating model performance more robustly by training/validating across multiple folds ✓
  • C. Feature storage
  • D. Logging metrics

Explanation: Cross-validation splits data into k folds, training on k-1 and validating on the held-out fold repeatedly, giving a lower-variance performance estimate and better hyperparameter selection.

9. In Hyperopt, what does fmin do?

  • A. Trains a single model
  • B. Searches the hyperparameter space to minimize an objective (loss) function ✓
  • C. Registers a model
  • D. Serves predictions

Explanation: fmin runs the optimization (e.g., TPE) over a defined search space to minimize the objective's returned loss, returning the best hyperparameters.

10. SparkTrials in Hyperopt is used to:

  • A. Parallelize tuning of single-node models across the Spark cluster ✓
  • B. Distribute a single deep-learning model
  • C. Store features
  • D. Serve models

Explanation: SparkTrials distributes independent Hyperopt trials (single-machine models) across the cluster's workers to speed up the search. For already-distributed Spark ML models, use Trials, not SparkTrials.

11. Which metric is appropriate for an imbalanced classification problem?

  • A. Accuracy alone
  • B. F1 score / AUC (precision-recall aware) ✓
  • C. RMSE
  • D. R-squared

Explanation: With class imbalance, accuracy is misleading; F1 (balances precision/recall) and ROC/PR-AUC give a truer picture. RMSE/R² are regression metrics.

12. A model scores high on training data but poorly on new data. This is:

  • A. Underfitting
  • B. Overfitting ✓
  • C. Data leakage
  • D. Good generalization

Explanation: High train / low test performance indicates overfitting — the model memorized noise. Remedies: regularization, more data, simpler model, cross-validation.

13. What does a pandas UDF (vectorized UDF) improve over a standard Python UDF in Spark?

  • A. Nothing
  • B. Performance — it processes data in batches via Arrow instead of row-by-row ✓
  • C. It removes the need for a cluster
  • D. It stores features

Explanation: pandas UDFs use Apache Arrow to transfer and process data in vectorized batches, far faster than row-at-a-time Python UDFs — useful for scaling scoring/feature logic.

14. The pandas API on Spark lets you:

  • A. Only use SQL
  • B. Run pandas-like code that executes distributed on Spark ✓
  • C. Serve models
  • D. Register features

Explanation: The pandas API on Spark (pyspark.pandas) offers a pandas-compatible interface that runs on Spark, so familiar pandas code scales to large datasets.

15. What does a model signature in MLflow capture?

  • A. The training duration
  • B. The expected input and output schema of the model ✓
  • C. The cluster size
  • D. The registry stage

Explanation: A signature records the model's input/output schema (column names/types), enabling validation at inference and clearer serving contracts; log an input_example alongside it.

16. Which Spark ML component converts a categorical string column to numeric indices?

  • A. VectorAssembler
  • B. StringIndexer ✓
  • C. StandardScaler
  • D. Imputer

Explanation: StringIndexer maps category strings to numeric indices (by frequency by default). It's usually followed by OneHotEncoder for non-ordinal categories.

17. After StringIndexer, which transformer creates binary columns for non-ordinal categories?

  • A. OneHotEncoder ✓
  • B. Bucketizer
  • C. MinMaxScaler
  • D. PCA

Explanation: OneHotEncoder turns indexed categories into sparse binary vectors so models don't treat category codes as ordinal magnitudes.

18. What does handleInvalid='skip' do on a StringIndexer at transform time?

  • A. Errors on unseen labels
  • B. Drops rows with previously unseen labels ✓
  • C. Imputes them
  • D. Keeps them as null

Explanation: handleInvalid controls unseen categories: 'error' (default) fails, 'skip' drops those rows, and 'keep' assigns them a special extra index.

19. Which estimator scales features to zero mean and unit variance?

  • A. MinMaxScaler
  • B. StandardScaler ✓
  • C. Normalizer
  • D. Bucketizer

Explanation: StandardScaler standardizes each feature (mean 0, std 1). MinMaxScaler rescales to a range (e.g., [0,1]); Normalizer scales rows to unit norm.

20. Feature scaling matters most for which model type?

  • A. Decision trees
  • B. Distance/gradient-based models (kNN, SVM, logistic/linear regression) ✓
  • C. Random forests
  • D. Naive Bayes

Explanation: Tree-based models are scale-invariant, but distance- and gradient-based models are sensitive to feature scale, so standardization helps convergence and fairness across features.

21. Which Spark ML class chains preprocessing and a model into one reproducible workflow?

  • A. Pipeline ✓
  • B. CrossValidator
  • C. ParamGridBuilder
  • D. VectorAssembler

Explanation: A Pipeline sequences stages (transformers + a final estimator) so fit/transform apply consistently, avoiding leakage and simplifying deployment.

22. randomSplit([0.8, 0.2], seed=42) is used to:

  • A. Tune hyperparameters
  • B. Create reproducible train/test sets ✓
  • C. Scale features
  • D. Register a model

Explanation: randomSplit divides a DataFrame into train/test; passing a fixed seed makes the split reproducible across runs.

23. Which Spark ML utility builds a grid of hyperparameter combinations for tuning?

  • A. ParamGridBuilder ✓
  • B. VectorAssembler
  • C. Bucketizer
  • D. PCA

Explanation: ParamGridBuilder constructs the parameter grid that CrossValidator or TrainValidationSplit searches over.

24. TrainValidationSplit differs from CrossValidator in that it:

  • A. Uses k folds
  • B. Evaluates each param combo on a single train/validation split (faster, higher variance) ✓
  • C. Cannot tune
  • D. Only works for regression

Explanation: TrainValidationSplit does one split per evaluation (cheaper, noisier), while CrossValidator averages over k folds (more robust, more compute).

25. Which evaluator would you use for a binary classifier's AUC?

  • A. RegressionEvaluator
  • B. BinaryClassificationEvaluator ✓
  • C. MulticlassClassificationEvaluator
  • D. ClusteringEvaluator

Explanation: BinaryClassificationEvaluator computes areaUnderROC/areaUnderPR. Multiclass covers accuracy/F1 for >2 classes; Regression covers RMSE/MAE/R².

26. Which metric is standard for a regression model's error magnitude?

  • A. F1
  • B. AUC
  • C. RMSE ✓
  • D. Precision

Explanation: RMSE (root mean squared error) measures regression error in the target's units, penalizing large errors more. MAE is a robust alternative; R² measures explained variance.

27. L1 (Lasso) regularization is notable because it:

  • A. Never shrinks weights
  • B. Can drive some coefficients to exactly zero (feature selection) ✓
  • C. Only scales features
  • D. Increases variance

Explanation: L1 penalizes absolute weights and can zero out coefficients, performing implicit feature selection. L2 (Ridge) shrinks weights smoothly without zeroing; elasticNet blends both.

28. Increasing a model's regularization strength generally:

  • A. Increases overfitting
  • B. Reduces overfitting by constraining weights ✓
  • C. Removes the need for data
  • D. Improves training accuracy

Explanation: More regularization constrains the model, lowering variance/overfitting (often at some cost to training fit) and improving generalization up to a point.

29. Which model is scale-invariant and handles nonlinear interactions without feature scaling?

  • A. Logistic regression
  • B. Random forest / gradient-boosted trees ✓
  • C. kNN
  • D. Linear regression

Explanation: Tree ensembles split on thresholds, so they're insensitive to feature scale and naturally capture nonlinearities and interactions.

30. How do you load a logged MLflow model for batch scoring in Spark?

  • A. mlflow.pyfunc.spark_udf(spark, model_uri) then apply as a column ✓
  • B. Copy the weights manually
  • C. Retrain it
  • D. Use Feature Store only

Explanation: mlflow.pyfunc.spark_udf wraps a registered/logged model as a Spark UDF so you can score a DataFrame at scale by adding a prediction column.

31. mlflow.search_runs() is used to:

  • A. Deploy a model
  • B. Query past runs (params/metrics) as a DataFrame to compare experiments ✓
  • C. Create features
  • D. Serve predictions

Explanation: search_runs returns runs (with their params/metrics/tags) for an experiment as a DataFrame, useful for programmatically finding the best run.

32. Which MLflow 'flavor' would a scikit-learn model typically be logged with?

  • A. mlflow.spark
  • B. mlflow.sklearn ✓
  • C. mlflow.keras
  • D. mlflow.r

Explanation: Models are logged with a flavor matching their library (mlflow.sklearn, mlflow.spark, mlflow.xgboost, ...); pyfunc provides a generic interface across flavors.

33. In AutoML, the 'primary metric' controls:

  • A. Cluster size
  • B. How the leaderboard ranks/selects the best model ✓
  • C. Feature Store writes
  • D. Serving latency

Explanation: The primary metric (e.g., F1, RMSE) is the objective AutoML optimizes and ranks trials by; choose it to match your business goal.

34. AutoML supports which problem types?

  • A. Only classification
  • B. Classification, regression, and forecasting ✓
  • C. Only clustering
  • D. Only forecasting

Explanation: Databricks AutoML handles classification, regression, and time-series forecasting, generating baseline models and editable notebooks for each.

35. To create a Feature Store feature table you typically:

  • A. Use fe.create_table / write features keyed by a primary key ✓
  • B. Register a model
  • C. Call fmin
  • D. Enable autolog

Explanation: You define a feature table with primary keys and write computed features to it (FeatureEngineeringClient/FeatureStoreClient), then reference it via lookups at training/inference.

36. A training set built from Feature Store lookups ensures:

  • A. Faster clusters
  • B. The same feature logic is reused at inference (no train-serve skew) ✓
  • C. Automatic tuning
  • D. Model registration

Explanation: create_training_set joins features by key so the exact feature definitions are packaged with the model, guaranteeing consistency between training and scoring.

37. In Hyperopt, hp.loguniform is appropriate for:

  • A. Categorical choices
  • B. Parameters spanning orders of magnitude (e.g., learning rate) ✓
  • C. Integers only
  • D. Boolean flags

Explanation: loguniform samples on a log scale, ideal for parameters like learning rate or regularization strength that vary across magnitudes. hp.choice is for categoricals.

38. A Hyperopt objective function must return:

  • A. The model
  • B. A dict with 'loss' (and status), where lower loss is better ✓
  • C. Accuracy directly
  • D. Nothing

Explanation: fmin minimizes 'loss', so return {'loss': value, 'status': STATUS_OK}. For a metric where higher is better (e.g., accuracy), return its negative.

39. Which is a sign of underfitting?

  • A. High train and high test accuracy
  • B. Low train and low test accuracy ✓
  • C. High train, low test
  • D. Perfect training fit

Explanation: Underfitting shows poor performance on both train and test — the model is too simple. Remedies: more features, a more complex model, less regularization.

40. The bias-variance tradeoff says that reducing variance (e.g., more regularization) usually:

  • A. Also reduces bias
  • B. Increases bias ✓
  • C. Removes noise
  • D. Eliminates the need for validation

Explanation: Constraining a model lowers variance but tends to raise bias; the goal is the sweet spot minimizing total error on unseen data.

41. Which is a valid way to handle class imbalance?

  • A. Ignore it
  • B. Class weights, resampling (over/under), or threshold tuning ✓
  • C. Only use accuracy
  • D. Drop the minority class

Explanation: Imbalance is addressed with class weighting, resampling, or adjusting the decision threshold — and evaluated with F1/PR-AUC rather than accuracy.

42. Which imputation strategy replaces missing numeric values with the column mean or median?

  • A. OneHotEncoder
  • B. Imputer ✓
  • C. Bucketizer
  • D. PCA

Explanation: Spark ML's Imputer fills missing numeric values with the mean or median (configurable) — fit on training data to avoid leakage.

43. Which is an example of data leakage?

  • A. Splitting before preprocessing
  • B. Including a feature that encodes the target (or future information) in training ✓
  • C. Using cross-validation
  • D. Scaling features

Explanation: Leakage occurs when training uses information unavailable at prediction time (e.g., a post-outcome field), producing over-optimistic metrics that collapse in production.

44. Increasing a decision tree's maxDepth tends to:

  • A. Reduce overfitting
  • B. Increase model complexity and risk of overfitting ✓
  • C. Scale features
  • D. Lower training accuracy

Explanation: Deeper trees fit training data more closely, raising variance/overfitting risk. Limiting maxDepth (or using ensembles) improves generalization.

45. Random forests reduce overfitting compared to a single tree by:

  • A. Using one deep tree
  • B. Averaging many de-correlated trees (bagging + feature subsampling) ✓
  • C. Removing features
  • D. Scaling data

Explanation: Random forests train many trees on bootstrapped samples with random feature subsets and average them, lowering variance versus a single tree.

46. featureImportances from a tree model tells you:

  • A. The best hyperparameters
  • B. How much each feature contributed to splits/impurity reduction ✓
  • C. The AUC
  • D. The learning rate

Explanation: Tree/ensemble models expose featureImportances, indicating each feature's relative contribution — useful for interpretation and feature selection.

47. Which discretizes a continuous column into buckets by specified split points?

  • A. Bucketizer ✓
  • B. StandardScaler
  • C. OneHotEncoder
  • D. Imputer

Explanation: Bucketizer maps continuous values into buckets given explicit splits; QuantileDiscretizer chooses splits from data quantiles.

48. Precision answers which question?

  • A. Of all actual positives, how many did we find?
  • B. Of all predicted positives, how many were correct? ✓
  • C. Overall correctness
  • D. Average error

Explanation: Precision = TP/(TP+FP): of predicted positives, the fraction correct. Recall = TP/(TP+FN): of actual positives, the fraction found. F1 balances the two.

49. Lowering a classifier's decision threshold typically:

  • A. Increases precision, lowers recall
  • B. Increases recall, lowers precision ✓
  • C. Has no effect
  • D. Improves both always

Explanation: A lower threshold labels more cases positive, catching more true positives (higher recall) but also more false positives (lower precision) — a tunable tradeoff.

50. R-squared (R²) measures:

  • A. Error in target units
  • B. The proportion of variance in the target explained by the model ✓
  • C. Precision
  • D. AUC

Explanation: R² is the fraction of variance explained (1 is perfect, 0 is no better than the mean). RMSE/MAE express error in the target's units.

51. MAE differs from RMSE in that MAE:

  • A. Penalizes large errors more
  • B. Treats all errors linearly (more robust to outliers) ✓
  • C. Is for classification
  • D. Cannot be negative only

Explanation: MAE averages absolute errors (linear, outlier-robust); RMSE squares errors first, penalizing large deviations more heavily.

52. A confusion matrix shows:

  • A. Feature correlations
  • B. Counts of TP/FP/TN/FN for a classifier ✓
  • C. Training curves
  • D. Hyperparameters

Explanation: The confusion matrix cross-tabs predicted vs actual classes (TP, FP, TN, FN), the basis for precision, recall, F1, and accuracy.

53. Why establish a simple baseline model first?

  • A. To deploy it
  • B. To set a reference performance that a complex model must beat ✓
  • C. To tune Hyperopt
  • D. To create features

Explanation: A baseline (e.g., majority class or mean predictor) gives a floor; if a sophisticated model can't beat it, something's wrong or the signal is weak.

54. When is single-node scikit-learn preferable to Spark ML?

  • A. For terabyte datasets
  • B. When data fits comfortably in one machine's memory (simpler, rich library) ✓
  • C. Always
  • D. Never

Explanation: For data that fits on one node, sklearn is simpler and feature-rich; Spark ML shines when data is too large for a single machine or you need distributed training.

55. A scalar pandas UDF operates on:

  • B. A pandas Series (batch), returning a Series of the same length ✓
  • C. The whole cluster
  • D. A model object

Explanation: A scalar pandas UDF receives a batch as a pandas Series and returns a Series, using Arrow for vectorized speed — ideal for scaling feature transforms/scoring.

Explanation: applyInPandas runs a pandas function on each group in parallel across the cluster — great for per-group modeling or vectorized group computations.

Explanation: An input_example documents expected inputs and lets MLflow infer the signature, improving validation and serving clarity.

  • D. It is slower always

61. Why is a fixed random seed important in ML experiments?

  • C. It scales the model
  • D. It prevents drift

Explanation: Seeds make stochastic steps (splits, shuffles, initializations) repeatable, so results and comparisons are reproducible.

Explanation: One-hot on very high-cardinality columns explodes dimensionality; target/frequency encoding, feature hashing, or embeddings are more practical.

64. Which is a benefit of storing ML training data as Delta tables?

  • B. Versioning/time travel and reproducible, consistent datasets ✓
  • C. Automatic tuning
  • D. Free serving

Explanation: Delta gives versioned, reproducible data (time travel) so experiments can be tied to a specific data snapshot — important for ML reproducibility and auditing.

65. PCA in a feature pipeline is used to:

  • A. Encode categories
  • B. Reduce dimensionality by projecting onto principal components ✓
  • C. Impute nulls
  • D. Tune models

Explanation: PCA reduces many correlated features to fewer orthogonal components capturing most variance — helpful for compression/denoising (at some interpretability cost).

66. Which is TRUE about the test set?

  • D. Retrain on it repeatedly

Explanation: The test set gives an unbiased final estimate and must not be used for tuning/selection (that's the validation set/CV), or it stops being unbiased.

67. elasticNetParam in Spark's regression blends:

  • D. Two models

Explanation: elasticNetParam=α mixes L1 (α=1) and L2 (α=0) penalties; regParam controls the overall strength.

68. Which correctly describes fit vs transform in a Pipeline?

  • B. They are identical
  • C. transform trains the model
  • D. fit serves predictions

Explanation: Estimators fit() to learn parameters (from training data); the resulting model/transformers transform() new data. Pipelines coordinate this across stages.

69. A gradient-boosted tree (GBT) builds trees:

  • A. Independently in parallel
  • B. Sequentially, each correcting the previous ensemble's errors ✓
  • C. By averaging
  • D. Without splits

Explanation: GBTs add trees sequentially, each fitting the residual errors of the current ensemble — often high accuracy but more tuning-sensitive than random forests.

71. Why prefer median over mean imputation for skewed data?

Explanation: For skewed distributions or outliers, the median better represents the central value than the mean, giving more sensible imputations.

Explanation: Random splits leak future info in time series; split by time so the model is validated on later periods, mirroring real forecasting.

79. Stratified sampling in a classification split ensures:

  • A. Equal feature scales
  • B. Class proportions are preserved in train and test ✓
  • C. Fewer rows
  • D. No nulls

Explanation: Stratification keeps the class distribution consistent across splits, important for imbalanced problems so evaluation is representative.

80. ChiSqSelector is used for:

  • D. Clustering

Explanation: ChiSqSelector picks top features by chi-squared statistic against a categorical label — a feature-selection transformer in Spark ML.
