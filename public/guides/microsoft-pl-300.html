Microsoft Power BI Data Analyst Associate (PL-300) — Study Guide

End-to-end Power BI: preparing data with Power Query, modeling with a star schema and DAX, visualizing and analyzing with reports, and deploying/maintaining with workspaces, RLS, and refresh.

~40–60 questions incl. case studies · 100 minutes · passing 700/1000 · four skill areas (prepare, model, visualize, deploy).

What it is

The Microsoft PL-300 (Power BI Data Analyst Associate) validates end-to-end Power BI skills: preparing data with Power Query, modeling with a star schema and DAX, visualizing and analyzing with reports, and deploying and maintaining content in the Power BI Service with workspaces, refresh, and Row-Level Security.

It is the industry-standard certification for Power BI analysts, covering the full lifecycle from raw source to a governed, shareable report — the skills to turn business questions into trustworthy, interactive dashboards.

Where it's used

  • Roles: Power BI Developer, BI/Data Analyst, Reporting Analyst, Analytics Consultant.
  • On the job: building semantic models (relationships, DAX measures), designing reports, configuring refresh/gateways, and securing data with RLS.
  • Career value: one of the most widely requested BI certifications globally; a baseline credential for Power BI roles.
  • For this portfolio: central to enterprise BI delivery, including insurance KPI and distributor-performance reporting.

In plain English

  • Power Query is the kitchen prep: clean and shape the raw data. The model is the recipe (tables + relationships + DAX). The report is the plated dish. The Service is the restaurant where you serve it to guests.
  • A star schema is a hub-and-spokes: one central facts table (sales) surrounded by simple lookup tables (date, product, region). It keeps everything fast and tidy.
  • A measure is a calculator that recomputes as you filter (great for totals); a calculated column is a value written into every row at refresh (takes space). Prefer measures for numbers.
  • Row-Level Security is giving each manager a keycard that only opens their floor — everyone opens the same report but sees only their own rows.

Exam shortcut tricks

  1. Measure vs calculated column: measures = query-time, respond to filters, no storage (use for aggregations). Calculated columns = refresh-time, stored per row. This is asked a lot.
  2. CALCULATE is the #1 DAX function — it changes filter context. If a question is about 'sales for X regardless of the slicer,' think CALCULATE.
  3. Time intelligence (TOTALYTD, SAMEPERIODLASTYEAR) needs a proper marked Date table — no date table = wrong results.
  4. DIVIDE(a,b) not a/b — DIVIDE handles divide-by-zero safely.
  5. Import = fast in-memory (needs refresh); DirectQuery = live/current but slower and limited. Composite/Dual = mix both.
  6. Query folding = push steps to the source (fast refresh). Remove unused columns EARLY to keep folding and shrink the model.
  7. One active relationship between two tables; others are inactive — activate with USERELATIONSHIP. Single-direction filtering is the safe default.

Study roadmap

  1. Prepare data (~25%) — connect to sources, Power Query transformations, data profiling, shaping, and query folding.
  2. Model data (~25%) — star schema, relationships & cardinality, DAX measures vs calculated columns, time intelligence.
  3. Visualize & analyze (~25%) — reports, visual selection, formatting, bookmarks, drillthrough, AI visuals.
  4. Deploy & maintain (~15%) — workspaces, apps, scheduled refresh, gateways, and Row-Level Security (RLS).
  5. DAX depth — CALCULATE, filter context vs row context, iterators (SUMX), and time-intelligence functions.
  6. Star schema discipline — fact vs dimension tables, avoiding many-to-many where possible.
  7. Practice case studies under time pressure; know Power BI Service vs Desktop responsibilities.

Study notes

Data modeling

  • Prefer a star schema: central fact table(s) surrounded by dimension tables; simpler, faster, and DAX-friendly.
  • Measures are calculated at query time using filter context (good for aggregations); calculated columns are computed at refresh and stored row-by-row.
  • Relationships: one-to-many is ideal; cross-filter direction is usually single (from dimension to fact).

DAX essentials

  • CALCULATE modifies filter context — the most important DAX function.
  • Row context (in calculated columns/iterators like SUMX) evaluates row by row; filter context comes from slicers/visuals/CALCULATE.
  • Time intelligence (TOTALYTD, SAMEPERIODLASTYEAR) requires a marked Date table.

Power Query

  • Transformations are recorded as ordered steps (M language); order matters.
  • Query folding pushes transformations back to the source for efficiency — preserved by native operations, broken by some custom steps.
  • Use data profiling (column quality/distribution) to find issues early.

Security & deployment

  • Row-Level Security (RLS): define roles with DAX filters; assign users in the Power BI Service.
  • Scheduled refresh needs an on-premises data gateway for on-prem sources.
  • Publish to a workspace; distribute to consumers via an app.

Hands-on projects

1. Insurance star-schema model in Power BI

Goal: Build a clean semantic model for premium/claims reporting.

Architecture & data model: Fact (premium/claims) surrounded by date, product, region, distributor dimensions; one-to-many single-direction relationships; marked date table.

Concepts covered:

  • Star schema: A central fact table joined to dimension tables — simplest, fastest structure for Power BI.
  • Relationships & cardinality: One-to-many from dimensions to the fact, defined with correct cardinality.
  • Single-direction filtering: Filters flow dimension → fact; avoids ambiguity/performance issues of bidirectional.
  • Date dimension (marked): A contiguous, marked date table enables correct time-intelligence.
  • Measures vs calculated columns: Measures compute at query time (no storage); calculated columns are stored per row.

Implementation steps:

  1. Model the fact and dimensions in a star.
  2. Set one-to-many, single-direction relationships; mark the date table.
  3. Create measures (written premium, loss ratio) rather than calculated columns.
  4. Reduce cardinality (split datetime) for performance.

Outcomes:

  • Fast, unambiguous model.
  • Correct time-intelligence.
  • Lean, performant dataset.

Stack: Power BI Desktop, DAX, Star schema

The modeling foundation behind the insurance KPI reports you deliver.

2. Power Query ETL with query folding

Goal: Clean and shape multi-source data efficiently.

Architecture & data model: Sources → Power Query (profile, remove columns, merge/append, foldable steps) → clean tables loaded to the model.

Concepts covered:

  • Power Query (M): The transformation layer that cleans and shapes data as ordered steps.
  • Query folding: Pushes steps back to the source as a native query for fast refresh.
  • Merge vs Append: Merge joins on a key; Append unions similarly-structured queries.
  • Data profiling: Column quality/distribution views to find issues early.
  • Remove-columns-early: Trimming unused columns early preserves folding and shrinks the model.

Implementation steps:

  1. Connect and profile sources.
  2. Remove unused columns early; keep steps foldable.
  3. Merge lookups and Append similar extracts.
  4. Verify folding is preserved.

Outcomes:

  • Fast, foldable refresh.
  • Clean, conformed source data.
  • Smaller model footprint.

Stack: Power Query, M language

Efficient, foldable ETL keeps enterprise datasets refreshing quickly.

3. DAX measures & time intelligence

Goal: Deliver YoY, YTD, and share-of-total metrics.

Architecture & data model: Base measures + CALCULATE variants + time-intelligence (YoY/YTD) built on the marked date table, refactored with VAR.

Concepts covered:

  • CALCULATE & filter context: The core function that modifies filter context to compute segmented metrics.
  • Row vs filter context: Row context (iterators/columns) vs filter context (slicers/visuals/CALCULATE).
  • Iterators (SUMX): Row-by-row computation then aggregation (e.g., Qty×Price line revenue).
  • Time intelligence (SAMEPERIODLASTYEAR, TOTALYTD): Period comparisons requiring a marked date table.
  • DIVIDE / VAR: DIVIDE handles divide-by-zero; VAR improves readability/performance.

Implementation steps:

  1. Write base measures, then CALCULATE variants for regions/segments.
  2. Add YoY with SAMEPERIODLASTYEAR + DIVIDE.
  3. Use SUMX for line-level revenue.
  4. Refactor with VAR for clarity/performance.

Outcomes:

  • Accurate YoY/YTD and segmented metrics.
  • Safe ratios (no divide-by-zero).
  • Readable, performant DAX.

Stack: DAX, Power BI

The analytical heart of executive insurance dashboards.

4. Report design, drillthrough & AI visuals

Goal: Build an interactive, decision-focused report.

Architecture & data model: A report leading with KPIs, with drillthrough to detail, slicers (synced), and AI visuals, tuned via edit-interactions.

Concepts covered:

  • Visual selection: Choose visuals to fit the question (KPI, line, bar, matrix).
  • Bookmarks & drillthrough: Save states and let users jump to filtered detail pages.
  • Slicers & sync slicers: On-canvas filters that can sync across pages.
  • Key influencers / Q&A visuals: AI visuals for driver analysis and natural-language questions.
  • Edit interactions: Control how selecting one visual filters/highlights others.

Implementation steps:

  1. Lead with KPIs; add trend/comparison/detail visuals.
  2. Configure drillthrough from summary to filtered detail.
  3. Add Key Influencers and Q&A visuals.
  4. Tune cross-visual interactions.

Outcomes:

  • Interactive, decision-focused report.
  • Self-service exploration.
  • Clear, controlled interactivity.

Stack: Power BI, Bookmarks, AI visuals

Executive-ready, self-service reporting — a core deliverable.

5. Deploy, secure & refresh in the Service

Goal: Publish a governed, secured, auto-refreshing report.

Architecture & data model: Published dataset/report with RLS roles, gateway + incremental refresh, distributed via an app and promoted through a deployment pipeline.

Concepts covered:

  • Workspaces & apps: Publish to a workspace and distribute to consumers via an app.
  • Row-Level Security (RLS): Roles with DAX filters (e.g., USERPRINCIPALNAME) restrict rows per user.
  • Gateways & scheduled refresh: On-prem gateway + schedule keep data current.
  • Incremental refresh: Refresh only recent partitions to cut time on large tables.
  • Deployment pipelines: Promote content across Dev/Test/Prod with rules.

Implementation steps:

  1. Publish to a workspace; define RLS roles.
  2. Configure gateway and scheduled/incremental refresh.
  3. Distribute via an app.
  4. Promote dev→test→prod with a deployment pipeline.

Outcomes:

  • Governed, secured distribution.
  • Timely, efficient refresh.
  • Controlled release management.

Stack: Power BI Service, RLS, Gateway

Governed distribution and refresh mirror real enterprise rollout.

Practice questions (100)

1. Which data model design is recommended for Power BI performance and usability?

  • A. A single flat table
  • B. A snowflake with deep hierarchies
  • C. A star schema (fact + dimensions) ✓
  • D. Many-to-many everywhere

Explanation: A star schema — a central fact table joined to dimension tables — is Microsoft's recommended model. It simplifies relationships, speeds up the VertiPaq engine, and makes DAX and filtering predictable.

2. What is the key difference between a measure and a calculated column?

  • A. Measures are stored per row; columns are computed at query time
  • B. Measures are computed at query time using filter context; calculated columns are computed at refresh and stored per row ✓
  • C. They are identical
  • D. Calculated columns cannot use DAX

Explanation: Measures evaluate dynamically at query time based on filter context (ideal for aggregations and slicer-responsive KPIs). Calculated columns are evaluated during refresh and physically stored, increasing model size.

3. Which DAX function is used to modify or override filter context?

  • A. SUM
  • B. CALCULATE ✓
  • C. RELATED
  • D. FORMAT

Explanation: CALCULATE is the cornerstone of DAX — it evaluates an expression in a modified filter context (adding, removing, or overriding filters). Mastering CALCULATE is essential for PL-300.

4. What does query folding do in Power Query?

  • A. Encrypts the query
  • B. Pushes transformation steps back to the source system for efficient processing ✓
  • C. Duplicates the data
  • D. Converts M to DAX

Explanation: Query folding translates applied steps into a single native source query (e.g., SQL) executed at the source, minimizing data transfer and improving refresh performance. Some transformations break folding.

5. How is Row-Level Security (RLS) implemented in Power BI?

  • A. By hiding visuals
  • B. By defining roles with DAX filter expressions and assigning users to roles ✓
  • C. By password-protecting the .pbix
  • D. By using bookmarks

Explanation: RLS is defined by creating roles with DAX filters on tables (e.g., [Region] = USERPRINCIPALNAME()) in Desktop, then assigning users/groups to those roles in the Power BI Service.

6. Which component is required to refresh a dataset that connects to an on-premises SQL Server?

  • A. A Power BI app
  • B. An on-premises data gateway ✓
  • C. A calculated table
  • D. A bookmark

Explanation: Scheduled refresh against on-premises sources requires an on-premises data gateway to securely bridge the Power BI Service and the local data source.

7. Which DAX function set requires a properly marked Date table to work correctly?

  • A. Text functions
  • B. Time-intelligence functions (e.g., TOTALYTD, SAMEPERIODLASTYEAR) ✓
  • C. Logical functions
  • D. Information functions

Explanation: Time-intelligence functions rely on a contiguous, marked Date table to compute periods like YTD or prior-year. Without a proper date dimension they return incorrect results.

8. An iterator like SUMX operates in which context?

  • A. Filter context only
  • B. Row context (evaluating expression per row, then aggregating) ✓
  • C. No context
  • D. Visual context only

Explanation: SUMX iterates a table row by row (row context), evaluates the expression for each row, then sums the results — useful when the calculation depends on per-row values before aggregation.

9. What is the recommended cross-filter direction for a standard one-to-many dimension→fact relationship?

  • A. Both directions by default
  • B. Single (from the dimension to the fact) ✓
  • C. None
  • D. Many-to-many

Explanation: Single-direction filtering from the dimension to the fact table is the default best practice. Bidirectional filtering can cause ambiguity and performance issues and should be used sparingly.

10. Which feature lets report users navigate from a summary visual to a detailed page filtered to the selected item?

  • A. Drillthrough ✓
  • B. Query folding
  • C. RLS
  • D. Incremental refresh

Explanation: Drillthrough lets a user right-click a data point and jump to a detail page automatically filtered to that context (e.g., from a category to that category's details), improving report exploration.

11. How do you distribute a finished report to a broad set of business consumers in the Power BI Service?

  • A. Email the .pbix file
  • B. Publish to a workspace and share it as an app ✓
  • C. Export to CSV
  • D. Screenshot each page

Explanation: The governed distribution path is to publish to a workspace and package the content as an app for consumers — providing controlled access, a clean navigation experience, and update management.

12. Which storage mode imports data into the Power BI model for fast in-memory performance?

  • A. DirectQuery
  • B. Import ✓
  • C. Live connection
  • D. Composite only

Explanation: Import mode loads data into the VertiPaq in-memory engine for the fastest queries (with scheduled refresh). DirectQuery queries the source live (no import, always current but slower); composite mixes both.

13. In DAX, RELATED() is used to:

  • A. Create a relationship
  • B. Fetch a column value from the 'one' side of a relationship into the 'many' side ✓
  • C. Sum a column
  • D. Filter a visual

Explanation: RELATED() retrieves a value from a related table on the one-side within a row context (e.g., in a calculated column on the fact table). RELATEDTABLE() goes the other direction.

14. Which visual is designed to show progress toward a target value?

  • A. Gauge / KPI visual ✓
  • B. Scatter chart
  • C. Map
  • D. Matrix

Explanation: Gauge and KPI visuals display a value against a target/goal, making progress and status immediately readable. Matrix/scatter/map serve other purposes.

15. What does the 'Manage relationships' cardinality 'one-to-many' imply?

  • A. Both tables have duplicate keys
  • B. The 'one' side has unique key values; the 'many' side can repeat them ✓
  • C. No filtering occurs
  • D. It's the same as many-to-many

Explanation: One-to-many means the dimension (one side) has unique keys and the fact (many side) references them repeatedly — the standard, well-performing star-schema relationship.

16. Which Power Query step reduces columns early to improve performance and folding?

  • A. Remove Other Columns / Choose Columns ✓
  • B. Add Custom Column
  • C. Group By
  • D. Merge Queries

Explanation: Removing unneeded columns early reduces data volume and often preserves query folding, improving refresh performance. Bringing in everything then trimming later is less efficient.

17. VAR in a DAX measure is used to:

  • A. Create a table
  • B. Store an intermediate value for readability and to avoid recomputation ✓
  • C. Define a relationship
  • D. Refresh the dataset

Explanation: VAR declares a variable evaluated once and reused within the measure, improving readability and performance (the expression isn't recomputed) and avoiding context surprises.

18. To analyze data without importing it and always see current source data, use:

  • A. Import mode
  • B. DirectQuery ✓
  • C. A calculated column
  • D. A bookmark

Explanation: DirectQuery leaves data in the source and issues queries at report time, so results are always current — at the cost of query performance and some DAX/modeling limitations.

19. Which feature captures a specific report state (filters, selections) for navigation or storytelling?

  • A. Bookmark ✓
  • B. Gateway
  • C. Dataflow
  • D. RLS role

Explanation: Bookmarks save a report's current state (filters, slicers, visibility) and can be used for buttons, navigation, and guided storytelling.

20. A Power BI dataflow is primarily used to:

  • A. Render visuals
  • B. Perform reusable, cloud-based Power Query ETL that multiple datasets can consume ✓
  • C. Apply RLS
  • D. Schedule the gateway

Explanation: Dataflows run Power Query transformations in the service and store the results (in the data lake), so multiple datasets/reports can reuse the same prepared, centrally-managed data.

21. Which DAX function returns values from a table expression, ignoring filters, for 'all' calculations?

  • A. ALL() ✓
  • B. SUM()
  • C. RELATED()
  • D. BLANK()

Explanation: ALL() removes filters from a table or columns, commonly used inside CALCULATE to compute totals or percentages that ignore the current visual's filters (e.g., % of grand total).

22. Incremental refresh in Power BI helps by:

  • A. Refreshing the entire dataset every time
  • B. Refreshing only recent/changed partitions, speeding refresh of large tables ✓
  • C. Disabling refresh
  • D. Removing relationships

Explanation: Incremental refresh partitions large tables by date and refreshes only the recent/changed partitions, dramatically reducing refresh time and load versus a full reload.

23. Which visual best displays hierarchical part-to-whole data (e.g., category → subcategory)?

  • A. Treemap ✓
  • B. Line chart
  • C. Gauge
  • D. Card

Explanation: A treemap shows nested rectangles sized by value, good for part-to-whole across a hierarchy. Line charts show trends; cards/gauges show single values.

24. In RLS, the DAX filter [Manager] = USERPRINCIPALNAME() achieves:

  • A. Static filtering for everyone
  • B. Dynamic per-user filtering based on the signed-in user's identity ✓
  • C. Column masking
  • D. Incremental refresh

Explanation: USERPRINCIPALNAME() returns the current user's login, so the role dynamically filters rows to those belonging to that user — dynamic RLS without a role per person.

25. Which DAX function iterates a table and averages a per-row expression?

  • A. AVERAGE
  • B. AVERAGEX ✓
  • C. SUM
  • D. COUNTROWS

Explanation: AVERAGEX(table, expr) evaluates expr per row (row context) then averages the results — needed when the value depends on a row-level calculation. AVERAGE works on a single column only.

26. A calculated table (e.g., a Date table via CALENDAR) is created using:

  • A. Power Query only
  • B. A DAX table expression ✓
  • C. A visualization
  • D. RLS

Explanation: Calculated tables are defined with DAX (e.g., CALENDAR/CALENDARAUTO or a table function) and computed at refresh — commonly used to generate a proper Date dimension.

27. The 'Mark as date table' setting is important because it:

  • A. Speeds up visuals
  • B. Enables correct time-intelligence calculations ✓
  • C. Applies RLS
  • D. Compresses data

Explanation: Marking a table as the date table ensures DAX time-intelligence functions (YTD, prior year) work correctly by giving them a contiguous, unique date column.

28. Which Power Query operation combines rows from two queries with the same columns?

  • A. Merge Queries
  • B. Append Queries ✓
  • C. Group By
  • D. Pivot

Explanation: Append Queries stacks rows of similarly-structured queries (a union). Merge Queries joins them side-by-side on a key (like a SQL join).

29. Merge Queries in Power Query is analogous to:

  • A. A UNION
  • B. A JOIN on a key ✓
  • C. A GROUP BY
  • D. A filter

Explanation: Merge combines two queries by matching a key column, similar to a SQL JOIN, letting you bring columns from one query into another.

30. A measure showing running total over dates typically uses:

  • A. TOTALYTD or a CALCULATE with FILTER on dates <= current ✓
  • B. AVERAGE
  • C. RELATED
  • D. DISTINCTCOUNT only

Explanation: Running/cumulative totals use time-intelligence (TOTALYTD) or CALCULATE(SUM(...), FILTER(ALL(Date), Date[Date] <= MAX(Date[Date]))) to accumulate up to the current context date.

31. To reduce model size, which is most effective?

  • A. Import every column at highest precision
  • B. Remove unused columns and reduce high-cardinality columns ✓
  • C. Add more calculated columns
  • D. Use DirectQuery for small tables

Explanation: VertiPaq compresses columns; high-cardinality and unused columns bloat the model. Removing them (and reducing precision where possible) shrinks size and speeds performance.

32. A slicer differs from a filter pane filter in that a slicer:

  • A. Cannot filter visuals
  • B. Is an on-canvas visual users interact with directly ✓
  • C. Only works in DirectQuery
  • D. Applies RLS

Explanation: A slicer is a visual placed on the report canvas for interactive filtering, whereas the Filters pane provides filter controls outside the canvas. Both filter visuals.

33. DISTINCTCOUNT(column) returns:

  • A. All rows
  • B. The number of unique values in the column ✓
  • C. The sum
  • D. The last value

Explanation: DISTINCTCOUNT counts unique values (a common KPI like unique customers). COUNT counts non-blank values; COUNTROWS counts rows of a table.

34. Which deployment feature promotes content through Dev → Test → Prod stages?

  • A. Deployment pipelines (Premium) ✓
  • B. Bookmarks
  • C. Slicers
  • D. Dataflows only

Explanation: Power BI deployment pipelines (Premium/PPU) manage promotion of content across Dev, Test, and Prod workspaces with comparison and rules, supporting governed release.

35. Sensitivity labels in Power BI are used to:

  • A. Speed up refresh
  • B. Classify and protect content (e.g., Confidential) with governance/encryption ✓
  • C. Create measures
  • D. Build slicers

Explanation: Sensitivity labels (Microsoft Purview Information Protection) classify reports/datasets and can enforce protection like encryption and access restrictions, aiding data governance.

36. Which visual interaction option lets one visual filter or highlight others?

  • A. Edit interactions (filter/highlight/none) ✓
  • B. RLS
  • C. Incremental refresh
  • D. Gateways

Explanation: 'Edit interactions' controls how selecting a data point in one visual affects others — filtering, cross-highlighting, or no interaction — key to report UX.

37. CALCULATE(SUM(Sales[Amt]), Sales[Region]="West") returns:

  • A. All-region sales
  • B. Sales filtered to the West region regardless of current visual filters on Region ✓
  • C. An error
  • D. Average sales

Explanation: CALCULATE overrides the filter context with Region = West, so the measure returns West sales even if the visual isn't filtered to West (it replaces any existing Region filter).

38. Which function counts the rows of a table in DAX?

  • A. COUNTROWS(table) ✓
  • B. COUNT(column)
  • C. SUM(table)
  • D. ROWS()

Explanation: COUNTROWS returns the number of rows in a table (or table expression). COUNT counts non-blank values in a single column.

39. The FILTER function in DAX returns:

  • A. A scalar
  • B. A table filtered by a condition (often used inside CALCULATE) ✓
  • C. A visual
  • D. A relationship

Explanation: FILTER(table, condition) returns a filtered table, commonly passed to CALCULATE or iterators to apply complex row-level filter logic.

40. Which is TRUE about relationships and inactive relationships?

  • A. Only one active relationship can exist between two tables; others are inactive and used via USERELATIONSHIP ✓
  • B. All relationships are always active
  • C. Inactive relationships cannot be used
  • D. There is no limit on active relationships

Explanation: Between two tables only one relationship is active at a time; additional ones are inactive and activated within a measure using USERELATIONSHIP inside CALCULATE.

41. Power Query's 'Column from Examples' feature:

  • A. Writes DAX
  • B. Infers a transformation from sample outputs you type ✓
  • C. Creates a relationship
  • D. Publishes the report

Explanation: Column from Examples generates M transformation logic by inferring the pattern from example values you provide — a fast way to build derived columns.

42. A key visual for showing distribution/outliers of a numeric field is:

  • A. Card
  • B. Scatter or box-and-whisker style visual ✓
  • C. KPI
  • D. Slicer

Explanation: Scatter charts (and custom box-plot visuals) show spread and outliers. Cards/KPIs show single values; slicers filter.

43. What does SUMX(Sales, Sales[Qty] * Sales[Price]) compute?

  • A. The sum of Qty only
  • B. Row-by-row Qty×Price, then the total (line-level revenue) ✓
  • C. The average price
  • D. The count of rows

Explanation: SUMX iterates each row computing Qty×Price (row context) and sums the results — the correct way to total a product of columns rather than multiplying aggregates.

44. Aggregations (aggregation tables) in Power BI improve performance by:

  • A. Removing relationships
  • B. Pre-summarizing large fact data so many queries hit the small aggregate instead of the detail ✓
  • C. Disabling DAX
  • D. Encrypting data

Explanation: Aggregation tables store pre-aggregated data; the engine transparently redirects compatible queries to them (often over a DirectQuery detail table), greatly speeding results.

45. Which is TRUE about DirectQuery limitations?

  • A. It supports all DAX and unlimited performance
  • B. Some DAX/features are restricted and performance depends on the source ✓
  • C. It imports data
  • D. It cannot connect to SQL

Explanation: DirectQuery keeps data at the source (always current) but has DAX/feature limitations and performance bound by the source system — trade-offs vs Import mode.

46. The 'Q&A' visual lets users:

  • A. Write M code
  • B. Ask natural-language questions and get an auto-generated visual ✓
  • C. Manage gateways
  • D. Set RLS

Explanation: The Q&A visual interprets natural-language questions against the model and returns a relevant visual — an AI feature that aids self-service exploration.

47. To hide a column from report view but keep it in the model, you:

  • A. Delete it
  • B. Set it to Hidden ✓
  • C. Add RLS
  • D. Use a slicer

Explanation: Hiding a column removes it from the Fields pane for report authors/consumers while keeping it available for relationships and measures — good for key/technical columns.

48. Which storage/refresh feature reduces refresh time on huge fact tables?

  • A. Incremental refresh with date partitions ✓
  • B. Bookmarks
  • C. Slicers
  • D. Q&A

Explanation: Incremental refresh partitions by date and refreshes only recent partitions, dramatically cutting refresh duration and resource use for large tables.

49. KEEPFILTERS inside CALCULATE is used to:

  • A. Remove all filters
  • B. Add a filter without removing existing filters on the same column ✓
  • C. Create a relationship
  • D. Hide a visual

Explanation: By default a CALCULATE filter replaces existing filters on that column; KEEPFILTERS intersects the new filter with the current context instead of overriding it.

50. A gateway in 'standard/enterprise' mode is needed when:

  • A. All data is in the cloud
  • B. Scheduled refresh or DirectQuery must reach on-premises/private data sources ✓
  • C. Using only sample data
  • D. Building visuals

Explanation: The on-premises data gateway bridges the Power BI service to on-prem or VNet-protected sources for refresh and DirectQuery; fully cloud SaaS sources often don't need it.
