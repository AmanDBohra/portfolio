Databricks Certified Data Engineer Associate — Study Guide

Core Lakehouse engineering: building ELT pipelines with Spark SQL and Python, incremental processing with Delta Lake and Auto Loader, productionizing with Delta Live Tables and Jobs, and governance with Unity Catalog.

~45 multiple-choice questions · 90 minutes · passing ~70% · no penalty for wrong answers.

What it is

The Databricks Certified Data Engineer Associate validates that you can build and maintain data pipelines on the Databricks Lakehouse Platform. It focuses on the day-to-day engineering skills: ingesting data incrementally, transforming it with Spark SQL and Python, storing it reliably in Delta Lake, and productionizing it with Delta Live Tables, Jobs, and Unity Catalog governance.

It is the entry-level engineering credential in the Databricks track. It proves you understand the Lakehouse model (one platform for both data-lake storage and warehouse-style analytics), the medallion architecture (bronze → silver → gold), and how Delta's transaction log gives ACID guarantees, time travel, and simple upserts on top of cheap cloud object storage.

Where it's used

  • Roles: Data Engineer, Analytics Engineer, BI/ETL Developer moving to the Lakehouse, or a data analyst broadening into engineering.
  • On the job: building bronze/silver/gold pipelines, incremental ingestion with Auto Loader/COPY INTO, and scheduled Jobs that feed dashboards and ML.
  • Career value: it is the recommended first Databricks certification and a prerequisite mindset for the Professional exam; widely requested for cloud data-platform roles.
  • For this portfolio: underpins the international insurance analytics delivery and the ETL/data-quality work, where reliable, governed pipelines are essential.

In plain English

  • Think of a restaurant kitchen. Raw ingredients arrive (Bronze), you wash and chop them (Silver), then plate finished dishes (Gold). That's the medallion architecture — data gets cleaner and more useful at each stage.
  • Delta Lake is like Google Docs for data: every change is saved with history, you can undo to any earlier version (time travel), and two people editing won't corrupt the file (ACID).
  • A 'managed' table is like a pet you own — if you get rid of it, it's gone (drop = data deleted). An 'external' table is like a rented apartment — you leave, but the building (the files) stays.
  • Auto Loader is a mailbox that notices new letters (files) the moment they arrive and only reads the new ones — it never re-reads yesterday's mail.

Exam shortcut tricks

  1. Managed vs external: LOCATION keyword = external (drop keeps files). No LOCATION = managed (drop deletes files). This distinction is asked constantly.
  2. OPTIMIZE = fewer, bigger files (fix small files). ZORDER = sort so filters skip data. VACUUM = permanently delete old files. Don't mix them up.
  3. Auto Loader = huge/continuous file volumes; COPY INTO = smaller/known batches. Both are idempotent (safe to re-run).
  4. Unity Catalog is always three levels: catalog.schema.table. To READ you need USE CATALOG + USE SCHEMA + SELECT — a missing traversal grant is a classic trick answer.
  5. MERGE = upsert (insert + update + delete in one go). If a question says 'insert new and update existing,' the answer is almost always MERGE.
  6. Job cluster = scheduled/automated (cheap, dies after). All-purpose cluster = interactive notebooks. Pick job cluster for pipelines.
  7. Time travel works only until VACUUM removes the old files (default 7-day retention). 'Why can't I time travel that far back?' → VACUUM.

Study roadmap

  1. Lakehouse fundamentals — understand the Lakehouse architecture, the difference between data lakes/warehouses, clusters (all-purpose vs job), notebooks, and Repos.
  2. Delta Lake essentials — ACID transactions, the transaction log, time travel, MERGE, OPTIMIZE, VACUUM, and managed vs external (unmanaged) tables.
  3. ELT with Spark SQL — CTAS, views vs tables vs temp views, handling nested/complex data, higher-order functions, and joins/set operations.
  4. Incremental processing — Structured Streaming basics, Auto Loader (cloudFiles), COPY INTO, and multi-hop (medallion: bronze/silver/gold) architecture.
  5. Delta Live Tables (DLT) — declarative pipelines, STREAMING LIVE TABLE vs LIVE TABLE, expectations for data quality, and pipeline modes.
  6. Production & orchestration — Databricks Jobs (tasks, dependencies, schedules, retries), Databricks SQL dashboards and alerts.
  7. Governance — Unity Catalog three-level namespace (catalog.schema.table), grants/permissions, and data object ownership.
  8. Practice: full-length timed tests until consistently 85%+; review every missed objective.

Study notes

Delta Lake

  • Delta = Parquet data files + an ordered JSON transaction log (_delta_log) giving ACID guarantees.
  • MANAGED tables: Databricks owns data + metadata; DROP deletes the data. EXTERNAL tables (LOCATION specified): DROP removes only metadata, files remain.
  • Time travel: query old versions with VERSION AS OF / TIMESTAMP AS OF; enabled by the transaction log.
  • OPTIMIZE compacts small files; ZORDER BY co-locates data for faster reads; VACUUM removes stale files (default 7-day retention).
  • MERGE INTO handles upserts (insert/update/delete) in one atomic operation — the basis for CDC.

Incremental ingestion

  • Auto Loader (spark.readStream.format('cloudFiles')) incrementally and idempotently ingests new files as they land; scales to millions of files.
  • COPY INTO is an idempotent SQL command for incremental loads of smaller/known file sets; re-running skips already-loaded files.
  • Medallion architecture: Bronze (raw), Silver (cleaned/conformed), Gold (aggregated/business-level).

Delta Live Tables

  • DLT is declarative: you define the target tables and transformations; DLT manages orchestration, dependencies, and error handling.
  • Use STREAMING LIVE TABLE for incremental/streaming sources; LIVE TABLE for tables recomputed on each run.
  • Expectations (CONSTRAINT ... EXPECT) enforce data quality: warn, drop, or fail on violation.

Unity Catalog & governance

  • Three-level namespace: catalog.schema.table (adds a layer above the classic schema.table).
  • Privileges granted with GRANT/REVOKE; USAGE/USE CATALOG and USE SCHEMA are needed to traverse to objects.
  • Managed by an account-level metastore shared across workspaces.

Practice questions (100)

1. What guarantees do Delta Lake tables provide that plain Parquet files do not?

  • A. Columnar compression
  • B. ACID transactions ✓
  • C. Schema-on-read only
  • D. Row-based storage

Explanation: Delta Lake adds an ordered transaction log on top of Parquet data files, providing ACID (atomicity, consistency, isolation, durability) transactions — concurrent reads/writes, all-or-nothing commits, and consistent snapshots. Parquet alone is just columnar files with no transactional guarantees.

2. You drop a MANAGED Delta table. What happens to the underlying data files?

  • A. They remain in cloud storage
  • B. They are deleted along with the metadata ✓
  • C. They are moved to a trash folder for 30 days
  • D. Only the transaction log is removed

Explanation: For a MANAGED table, Databricks owns both the metadata and the data, so DROP TABLE deletes the underlying files. For an EXTERNAL table (created with LOCATION), DROP removes only the metadata and the files remain in storage.

3. Which tool is designed to incrementally and idempotently ingest large numbers of new files as they arrive in cloud storage?

  • A. COPY INTO
  • B. Auto Loader (cloudFiles) ✓
  • C. CREATE TABLE AS SELECT
  • D. VACUUM

Explanation: Auto Loader (spark.readStream.format('cloudFiles')) is purpose-built to incrementally process new files as they land, tracking what's been ingested so it scales efficiently to millions of files. COPY INTO also does incremental loads but is better for smaller, known file sets.

4. In the medallion architecture, which layer holds raw, unprocessed ingested data?

  • A. Gold
  • B. Silver
  • C. Bronze ✓
  • D. Platinum

Explanation: Bronze holds raw ingested data (as-is from source). Silver holds cleaned, filtered, and conformed data. Gold holds business-level aggregates ready for analytics and reporting.

5. Which command compacts many small files in a Delta table into fewer larger files?

  • A. VACUUM
  • B. OPTIMIZE ✓
  • C. REFRESH
  • D. ANALYZE

Explanation: OPTIMIZE compacts small files into larger ones to improve read performance. Optionally ZORDER BY co-locates related data. VACUUM is different — it permanently removes files no longer referenced by the transaction log (default 7-day retention).

6. What is the correct Unity Catalog namespace to reference a table?

  • A. database.table
  • B. catalog.schema.table ✓
  • C. workspace.database.table
  • D. schema.catalog.table

Explanation: Unity Catalog uses a three-level namespace: catalog.schema.table. This adds the catalog layer above the traditional two-level schema.table (database.table) naming.

7. Which SQL operation performs an atomic upsert (insert new rows, update matching rows) in Delta Lake?

  • A. INSERT OVERWRITE
  • B. MERGE INTO ✓
  • C. UPDATE ... JOIN
  • D. COPY INTO

Explanation: MERGE INTO matches a source against a target on a condition and can INSERT, UPDATE, and DELETE in a single atomic transaction — the standard pattern for upserts and change-data-capture in Delta.

8. In Delta Live Tables, what do 'expectations' provide?

  • A. Automatic cluster scaling
  • B. Declarative data-quality constraints on records ✓
  • C. Version control for notebooks
  • D. Cost estimates for a pipeline run

Explanation: DLT expectations are data-quality constraints (CONSTRAINT ... EXPECT ...) applied to records flowing through the pipeline. Based on the policy you can warn (track), drop the violating rows, or fail the pipeline.

9. Which cluster type is most appropriate for a scheduled, automated production pipeline?

  • A. All-purpose cluster
  • B. Job cluster ✓
  • C. SQL warehouse (serverless)
  • D. Single-node cluster

Explanation: Job clusters are created for a specific job run and terminate when it finishes — cheaper and isolated, ideal for automated production workloads. All-purpose clusters are for interactive/collaborative development.

10. How can you query a previous version of a Delta table?

  • A. It is not possible once overwritten
  • B. Using VERSION AS OF or TIMESTAMP AS OF (time travel) ✓
  • C. By restoring a manual backup
  • D. Using VACUUM with a version number

Explanation: Delta time travel lets you read earlier snapshots with SELECT ... VERSION AS OF n or TIMESTAMP AS OF '...'. This is possible because the transaction log records every version. Note that VACUUM can eventually remove old files past the retention window, limiting how far back you can travel.

11. What does COPY INTO guarantee when the same command is run twice on the same source files?

  • A. Files are loaded again, creating duplicates
  • B. It is idempotent — already-loaded files are skipped ✓
  • C. The target table is overwritten
  • D. It raises an error

Explanation: COPY INTO is idempotent: it tracks which files have already been ingested, so re-running it skips those files and only loads new ones — preventing duplicates in incremental loads.

12. Which privilege chain is required for a user to read a table in Unity Catalog?

  • A. Only SELECT on the table
  • B. USE CATALOG on the catalog, USE SCHEMA on the schema, and SELECT on the table ✓
  • C. OWNER on the workspace
  • D. MODIFY on the metastore

Explanation: To reach an object, a user needs traversal privileges: USE CATALOG on the parent catalog and USE SCHEMA on the parent schema, plus SELECT on the table itself. Missing a traversal grant blocks access even if SELECT is granted.

13. Which command runs another notebook inline, sharing the same execution context?

  • A. %sh
  • B. %run ./other_notebook ✓
  • C. dbutils.notebook.run()
  • D. %pip

Explanation: %run ./notebook executes the target notebook in the same context, so its variables/functions become available. dbutils.notebook.run() runs it as a separate ephemeral job with its own context and returns only a string.

14. What is the correct way to create a table from a query result?

  • A. CREATE VIEW ... AS
  • B. CREATE TABLE ... AS SELECT (CTAS) ✓
  • C. INSERT INTO SELECT only
  • D. COPY INTO

Explanation: CREATE TABLE ... AS SELECT (CTAS) materializes the query result as a new managed Delta table. A view stores only the query definition; INSERT requires an existing table.

15. A temporary view created with CREATE TEMP VIEW is visible:

  • A. To all users globally
  • B. Only within the current SparkSession/notebook session ✓
  • C. Permanently in the metastore
  • D. Only in Databricks SQL

Explanation: A temp view is scoped to the current SparkSession and disappears when it ends. A global temp view lives in the global_temp database for the cluster's life; a regular view is persisted in the metastore.

16. Which Delta feature lets Auto Loader adapt when new columns appear in incoming files?

  • A. VACUUM
  • B. Schema evolution (cloudFiles.schemaEvolutionMode) ✓
  • C. ZORDER
  • D. Time travel

Explanation: Auto Loader supports schema inference and evolution; when new columns appear it can add them (e.g., addNewColumns mode), often restarting the stream to pick up the updated schema.

17. DESCRIBE HISTORY on a Delta table shows:

  • A. The table's columns
  • B. The transaction/version history including operations and timestamps ✓
  • C. The physical file paths
  • D. The cluster logs

Explanation: DESCRIBE HISTORY returns the commit history — version numbers, operations (WRITE, MERGE, OPTIMIZE), timestamps, and user — which supports auditing and time travel.

18. Which statement about a Delta table's schema enforcement is true?

  • A. It silently drops mismatched columns
  • B. Writes that don't match the schema are rejected unless schema evolution is enabled ✓
  • C. It converts types automatically
  • D. Schema is never enforced

Explanation: Delta enforces schema on write: a write with mismatched columns/types fails, protecting data quality. You can opt into mergeSchema/schema evolution to allow additive changes.

19. What does the CREATE TABLE ... USING DELTA LOCATION '/path' statement produce?

  • A. A managed table
  • B. An external (unmanaged) table ✓
  • C. A temporary view
  • D. A streaming table

Explanation: Specifying LOCATION makes the table external — Databricks manages only the metadata, and DROP leaves the files at that path intact. Without LOCATION it would be a managed table.

20. In DLT, which mode continuously processes data as it arrives versus running once and stopping?

  • A. Triggered vs Continuous pipeline mode ✓
  • B. Batch vs Micro mode
  • C. Eager vs Lazy
  • D. Bronze vs Gold

Explanation: DLT pipelines run in Triggered mode (process available data then stop — good for scheduled batch) or Continuous mode (keep running, processing data as it arrives — for low-latency needs).

21. Which is the most efficient way to remove all rows from a large Delta table while keeping the schema?

  • A. DROP TABLE then recreate
  • B. DELETE FROM table
  • C. TRUNCATE TABLE ✓
  • D. VACUUM

Explanation: TRUNCATE TABLE removes all rows quickly while preserving the table and schema. DELETE FROM works but rewrites/marks files row-wise; DROP removes the table entirely.

22. A job needs to pass a parameter into a notebook at runtime. What feature is used?

  • A. Widgets (dbutils.widgets) ✓
  • B. VACUUM
  • C. ZORDER
  • D. Section Access

Explanation: dbutils.widgets defines input parameters (text, dropdown, etc.) that can be set by a Job or the UI and read in the notebook with dbutils.widgets.get() — enabling parameterized, reusable notebooks.

23. What happens when a task in a multi-task Databricks Job fails and retries are configured?

  • A. The whole workspace restarts
  • B. The task is retried up to the configured limit; dependent downstream tasks wait ✓
  • C. All tasks are skipped
  • D. The cluster is deleted

Explanation: With retries configured, a failed task is re-attempted up to the set limit. Downstream tasks that depend on it only run once it succeeds; if it ultimately fails, dependents are skipped.

24. Which is TRUE about managed vs external tables regarding storage location?

  • A. Managed tables store data in a location Databricks controls; external tables use a user-specified path ✓
  • B. Both always use the same path
  • C. External tables cannot be Delta
  • D. Managed tables cannot be queried

Explanation: Managed tables live in the metastore-managed storage location; external tables point to a path you specify with LOCATION. This affects what DROP deletes (data for managed, metadata only for external).

25. To connect a notebook to version control for collaboration, you use:

  • A. Databricks Repos (Git integration) ✓
  • B. VACUUM
  • C. DBFS root
  • D. A SQL warehouse

Explanation: Databricks Repos integrates notebooks with Git providers so teams can branch, commit, and review changes — the standard way to version-control Databricks code.

26. Which command adds a new column to an existing Delta table?

  • A. UPDATE TABLE
  • B. ALTER TABLE ... ADD COLUMNS ✓
  • C. MERGE COLUMN
  • D. CREATE COLUMN

Explanation: ALTER TABLE <t> ADD COLUMNS (col type) modifies the table schema to include new columns. Delta records this as a schema change in the transaction log.

27. CREATE OR REPLACE TABLE differs from DROP + CREATE because it:

  • A. Keeps the table's history/version lineage in place ✓
  • B. Deletes the catalog
  • C. Cannot be used with Delta
  • D. Requires a view

Explanation: CREATE OR REPLACE TABLE atomically replaces contents while preserving the table object and its Delta history (a new version), unlike DROP + CREATE which removes the table and its history.

28. Which function parses a JSON string column into a struct you can query by field?

  • A. to_json
  • B. from_json ✓
  • C. explode
  • D. flatten

Explanation: from_json(col, schema) converts a JSON string into a struct/map so nested fields can be accessed. to_json does the reverse; explode turns array elements into rows.

29. explode() is used to:

  • A. Delete rows
  • B. Turn each element of an array column into its own row ✓
  • C. Compress files
  • D. Join tables

Explanation: explode() generates one output row per element of an array (or key/value of a map), flattening nested collections into a tabular form.

30. In DLT, which expectation clause DROPS records that violate the rule?

  • A. EXPECT (warn only)
  • B. EXPECT ... ON VIOLATION DROP ROW ✓
  • C. EXPECT ... ON VIOLATION FAIL UPDATE
  • D. CONSTRAINT PRIMARY KEY

Explanation: ON VIOLATION DROP ROW discards violating records (keeping the pipeline running). FAIL UPDATE stops the pipeline; the default (no clause) only tracks/warns while keeping the rows.

31. A Unity Catalog volume is used to:

  • A. Store tabular Delta tables
  • B. Govern access to non-tabular files (e.g., unstructured data) in cloud storage ✓
  • C. Replace a SQL warehouse
  • D. Define RLS

Explanation: Volumes provide governed storage for non-tabular files (images, PDFs, CSV landing zones, etc.) within Unity Catalog, so file access is managed with the same permission model as tables.

32. INSERT OVERWRITE on a Delta table:

  • A. Appends rows
  • B. Replaces the table's (or partition's) data with the query result atomically ✓
  • C. Deletes the schema
  • D. Creates a view

Explanation: INSERT OVERWRITE replaces existing data (whole table or matching partitions) with new rows in a single atomic Delta commit, useful for full or partition reloads.

33. Which is TRUE about a global temp view?

  • A. It persists forever in the metastore
  • B. It lives in the global_temp schema and is available across sessions on the same cluster until it terminates ✓
  • C. It is the same as a managed table
  • D. It cannot be queried

Explanation: A global temp view is stored in global_temp and shared across sessions attached to the same cluster, lasting until the cluster ends — broader than a session-scoped temp view but still not persisted.

34. To restore a Delta table to an earlier version, you use:

  • A. RESTORE TABLE ... TO VERSION AS OF n ✓
  • B. VACUUM
  • C. OPTIMIZE
  • D. REFRESH

Explanation: RESTORE TABLE <t> TO VERSION AS OF n (or TIMESTAMP AS OF) reverts the table to a prior state as a new commit, leveraging Delta's version history.

35. Which read pattern is used for streaming ingestion from a Delta table?

  • A. spark.read.table
  • B. spark.readStream.table ✓
  • C. COPY INTO
  • D. CREATE VIEW

Explanation: spark.readStream.table('name') (or .format('delta').load(path)) treats the Delta table as a streaming source, processing new commits incrementally.

36. Partitioning a Delta table by a high-cardinality column (e.g., customer_id) is discouraged because it:

  • A. Improves performance always
  • B. Creates too many small partitions/files, hurting performance ✓
  • C. Encrypts data
  • D. Is required by Unity Catalog

Explanation: Partitioning on high-cardinality columns produces many tiny partitions and small files, degrading performance. Partition on low-cardinality columns (e.g., date) or rely on ZORDER for filtering.

37. The purpose of the medallion Gold layer is to:

  • A. Store raw data
  • B. Provide business-level, aggregated data ready for reporting/ML ✓
  • C. Hold rejected records
  • D. Cache the cluster

Explanation: Gold tables contain curated, aggregated, business-ready data (e.g., KPIs, feature tables) consumed by dashboards and ML — the refined end of bronze→silver→gold.

38. Which SQL clause in COPY INTO restricts which files are loaded by pattern?

  • A. PATTERN / FILES option ✓
  • B. WHERE only
  • C. LIMIT
  • D. ZORDER

Explanation: COPY INTO supports FILES (explicit list) and PATTERN (glob) options to control which files in the source location are ingested, alongside FORMAT options.

39. Which magic command lets you write SQL in a Python notebook cell?

  • A. %python
  • B. %sql ✓
  • C. %md
  • D. %sh

Explanation: %sql at the top of a cell runs that cell as SQL regardless of the notebook's default language. %md is markdown, %sh is shell, %python is Python.

40. dbutils.fs.ls('/path') is used to:

  • A. List files in a storage path ✓
  • B. Run a SQL query
  • C. Create a cluster
  • D. Grant permissions

Explanation: dbutils.fs provides filesystem utilities; ls() lists files/directories at a path (DBFS or mounted/UC volume). Other dbutils.fs commands include cp, mv, rm, and mkdirs.

41. DESCRIBE EXTENDED (or DETAIL) on a table shows:

  • A. Only column names
  • B. Detailed metadata such as location, format, and properties ✓
  • C. The data rows
  • D. The cluster logs

Explanation: DESCRIBE EXTENDED/DETAIL returns table metadata — location, provider/format, owner, and properties — useful to confirm whether a table is managed or external and where its files live.

42. array_contains(col, value) returns:

  • A. The array length
  • B. True if the array column contains the value ✓
  • C. The first element
  • D. A struct

Explanation: array_contains checks membership, returning a boolean. Related array functions include size(), element_at(), and explode().

43. CREATE SCHEMA (a.k.a. DATABASE) in Unity Catalog is created inside:

  • A. A table
  • B. A catalog ✓
  • C. A cluster
  • D. A notebook

Explanation: Schemas live within a catalog (catalog.schema.table). CREATE SCHEMA catalog.name creates it under the specified catalog.

44. Which is TRUE about DROP SCHEMA ... CASCADE?

  • A. It only drops empty schemas
  • B. It drops the schema and all objects within it ✓
  • C. It cannot be used
  • D. It keeps the tables

Explanation: CASCADE drops the schema together with all contained tables/views. Without CASCADE, dropping a non-empty schema fails (RESTRICT behavior).

45. Which function returns the source file name during ingestion (useful metadata)?

  • A. input_file_name() ✓
  • B. current_user()
  • C. now()
  • D. uuid()

Explanation: input_file_name() returns the file each row came from, commonly captured in bronze tables for lineage and debugging.

46. CAST(value AS INT) is used to:

  • A. Rename a column
  • B. Convert a value's data type ✓
  • C. Filter rows
  • D. Join tables

Explanation: CAST converts a value from one type to another (e.g., string to int). Invalid casts return null (or error in strict modes).

47. A table property like delta.deletedFileRetentionDuration controls:

  • A. Chart colors
  • B. How long deleted data files are retained (affecting VACUUM/time travel) ✓
  • C. Cluster size
  • D. User permissions

Explanation: This Delta table property sets the retention window for files no longer referenced, governing how far back time travel works and what VACUUM can remove.

48. Which is the recommended way to reference secrets (e.g., a DB password) in code?

  • A. Hard-code them in the notebook
  • B. dbutils.secrets.get(scope, key) from a secret scope ✓
  • C. Store in a public table
  • D. Put them in the table name

Explanation: Secret scopes store credentials securely; dbutils.secrets.get retrieves them at runtime (redacted in output), avoiding hard-coded secrets in code.

49. A streaming table in DLT is defined in SQL with:

  • A. CREATE STREAMING LIVE TABLE ✓
  • B. CREATE TEMP VIEW
  • C. CREATE MATERIALIZED TABLE
  • D. CREATE INDEX

Explanation: In DLT SQL, CREATE STREAMING LIVE TABLE (or @dlt.table on a streaming read in Python) declares an incrementally-processed streaming table; LIVE TABLE is recomputed each run.

50. Which clause makes a COPY INTO or read tolerant of malformed records by capturing them?

  • A. badRecordsPath / rescued data column ✓
  • B. ZORDER
  • C. VACUUM
  • D. QUALIFY

Explanation: Options like badRecordsPath (or Auto Loader's _rescued_data column) capture records that don't match the schema so the pipeline can continue and you can inspect the bad rows.

51. The main advantage of a managed table for a new pipeline is:

  • A. It never stores data
  • B. Databricks manages the storage lifecycle, simplifying cleanup and governance ✓
  • C. It cannot be dropped
  • D. It disables time travel

Explanation: Managed tables let Databricks handle the underlying storage location and lifecycle (DROP removes data), simplifying management when you don't need to control an external path.

52. Which is TRUE about a Delta table's _delta_log directory?

  • A. It stores the actual data
  • B. It stores JSON commit files (and periodic Parquet checkpoints) that define table state ✓
  • C. It is optional
  • D. It holds cluster logs

Explanation: _delta_log contains ordered JSON transaction commits (plus periodic Parquet checkpoint files) that record every change, enabling ACID, time travel, and consistent reads.

53. To load JSON files with a known schema efficiently, you should:

  • A. Always infer the schema
  • B. Provide an explicit schema to avoid an inference pass ✓
  • C. Convert to CSV first
  • D. Disable the transaction log

Explanation: Supplying a schema (StructType or DDL string) avoids Spark scanning the data to infer types, speeding reads and preventing type mis-inference.

54. current_timestamp() captured at load is useful to:

  • A. Encrypt rows
  • B. Record when each record was ingested (audit/lineage) ✓
  • C. Sort the cluster
  • D. Create a view

Explanation: Stamping an ingestion timestamp supports auditing, debugging, and incremental logic (e.g., knowing when bronze data arrived).

55. A CTAS with a PARTITIONED BY clause on a date column:

  • A. Is invalid
  • B. Creates a table physically partitioned by that column for pruning ✓
  • C. Encrypts partitions
  • D. Removes the schema

Explanation: CREATE TABLE ... PARTITIONED BY (dt) organizes files by the partition column, enabling partition pruning for filters on it — best for low-cardinality columns like dates.

56. Which best describes a view's performance vs a table?

  • A. A view stores results, so it's always faster
  • B. A view re-runs its query each time it's accessed (no stored data) ✓
  • C. A view cannot be queried
  • D. A view is encrypted

Explanation: A (standard) view holds only the query definition and recomputes on each access — always current but repeats the work. Tables/materialized results store data for faster reuse.

57. Which Auto Loader option specifies where inferred schema info is stored?

  • A. cloudFiles.schemaLocation ✓
  • B. checkpointLocation only
  • C. ZORDER
  • D. maxRows

Explanation: cloudFiles.schemaLocation persists the inferred/evolving schema for an Auto Loader stream so it's tracked across restarts and can evolve.

58. To grant a group read access to a table in Unity Catalog, you run:

  • A. GRANT SELECT ON TABLE ... TO `group` ✓
  • B. ALLOW READ
  • C. SET ACCESS
  • D. VACUUM

Explanation: GRANT SELECT ON TABLE catalog.schema.table TO `group` gives read access; traversal privileges (USE CATALOG/USE SCHEMA) are also required.

59. Which is a benefit of the medallion Silver layer?

  • A. Stores raw untouched data
  • B. Holds cleaned, conformed, joined data ready for analytics/further modeling ✓
  • C. Only stores rejected rows
  • D. Caches the cluster

Explanation: Silver refines bronze: cleansing, deduping, type-casting, and conforming/joining data into a queryable, trustworthy state that gold aggregates build on.

60. MERGE ... WHEN NOT MATCHED THEN INSERT handles:

  • A. Updates only
  • B. New records that don't exist in the target ✓
  • C. Deletes only
