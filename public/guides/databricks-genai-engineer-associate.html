Databricks Certified Generative AI Engineer Associate — Study Guide

Designing and building production LLM applications: RAG with vector search, prompt design, model selection, chains/agents, evaluation, deployment with Model Serving, and governance on Mosaic AI.

~45 questions · 90 minutes · scenario-based around RAG and LLM app design · passing ~70%.

What it is

The Databricks Certified Generative AI Engineer Associate validates the ability to design and build production LLM applications. It covers Retrieval-Augmented Generation (RAG), embeddings and vector search, prompt engineering, chains and agents, model selection, evaluation (groundedness, relevance), deployment via Model Serving, and governance/safety on the Mosaic AI stack.

It proves you can go beyond calling an LLM to engineering a reliable, grounded, evaluated, and governed AI system — the skills needed to ship GenAI features that businesses can trust.

Where it's used

  • Roles: GenAI/ML Engineer, AI Application Developer, Data Scientist building LLM solutions.
  • On the job: building RAG assistants over enterprise knowledge, wiring vector search, adding guardrails and evaluation, and deploying LLM endpoints.
  • Career value: one of the most in-demand modern skill sets; demonstrates practical, production-oriented Generative AI capability.
  • For this portfolio: directly supports the GenAI/RAG analytics-assistant work and translating advanced AI into business-facing tools.

In plain English

  • RAG is an open-book exam for the AI: instead of answering from memory (and guessing), it first looks up the relevant page (retrieval) and answers from what it found — far fewer made-up answers.
  • Embeddings turn text into coordinates on a map, so 'car' and 'automobile' sit close together. Retrieval just finds the nearest neighbors to your question.
  • Chunking is tearing a book into index cards so you can grab just the right few cards instead of hauling the whole book into the prompt.
  • Temperature is the AI's creativity dial: low = careful and predictable (facts), high = imaginative (brainstorming).

Exam shortcut tricks

  1. Hallucination in RAG is usually a RETRIEVAL problem: fix chunking/embeddings/retrieval and tell the model 'answer only from context, else say I don't know.' Raising temperature makes it WORSE.
  2. RAG quality = 3 metrics: context relevance (did we fetch the right stuff?), groundedness (is the answer supported?), answer relevance (did it address the question?).
  3. Fine-tuning = teach STYLE/behavior (permanent). RAG = supply fresh/proprietary FACTS (no retraining). 'Frequently changing knowledge' → RAG.
  4. Query and documents must use the SAME embedding model (and dimension) — a favorite trick answer.
  5. Exact terms/acronyms failing? Add hybrid (keyword + semantic) search.
  6. Retrieve broad, then RE-RANK to a precise few — better than a huge top-k that adds noise.
  7. Lower temperature (near 0) for factual/deterministic; higher for creative. Cap max_tokens to control length/cost.

Study notes

Retrieval-Augmented Generation

  • RAG grounds an LLM by retrieving relevant documents and injecting them into the prompt, reducing hallucination and enabling up-to-date/proprietary knowledge.
  • Pipeline: chunk documents → embed chunks → store vectors → embed the query → retrieve top-k similar chunks → build a grounded prompt → generate.
  • Chunk size/overlap trade off context completeness vs precision and token cost.

Embeddings & vector search

  • Embeddings map text to vectors so semantic similarity becomes vector distance (cosine/dot).
  • Databricks Vector Search indexes embeddings and can auto-sync from a Delta table (Delta Sync Index).
  • Retrieval quality depends on the embedding model and chunking, not just the LLM.

Evaluation

  • Key RAG metrics: groundedness/faithfulness (answer supported by context), answer relevance, and context relevance/recall.
  • LLM-as-a-judge can score responses; MLflow provides evaluation tooling for GenAI.

Deployment & governance

  • Log models with MLflow; serve via Model Serving endpoints; call hosted LLMs via Foundation Model APIs.
  • Governance: manage models/functions in Unity Catalog, filter PII, and add guardrails; monitor for drift and quality.

Hands-on projects

1. RAG analytics assistant over BI documentation

Goal: Answer plain-English questions from analytics/policy docs without hallucinating numbers.

Architecture & data model: Docs → chunk → embed → Databricks Vector Search (Delta Sync Index) → retrieve top-k → grounded prompt → LLM → cited answer.

Concepts covered:

  • RAG pipeline: Retrieve relevant context, then generate a grounded answer — reduces hallucination and uses current/proprietary data.
  • Chunking & overlap: Split docs into passages with slight overlap to preserve cross-boundary context.
  • Embeddings: Vector representations where semantically similar text is close, enabling similarity retrieval.
  • Vector Search retrieval: Index embeddings and fetch top-k nearest chunks for a query.
  • Grounded generation: Instruct the model to answer only from retrieved context and cite sources; abstain otherwise.

Implementation steps:

  1. Chunk documents with sensible size/overlap; embed and index in Vector Search.
  2. Embed the query; retrieve top-k relevant chunks.
  3. Build a grounded prompt instructing answer-from-context + citations.
  4. Return an honest 'not found' when context is insufficient.

Outcomes:

  • Assistant that answers from real docs, not guesses.
  • Cited, verifiable responses.
  • Up-to-date knowledge without retraining.

2. Retrieval quality tuning & hybrid search

Goal: Improve answer relevance for jargon/acronym-heavy insurance queries.

Architecture & data model: Broad vector+keyword retrieval → metadata filter → re-ranker → precise top-few context, evaluated on a labeled set.

Concepts covered:

  • Chunk-size tuning: Balance context completeness vs precision and token cost by adjusting size/overlap.
  • Re-ranking: A cross-encoder re-scores initial candidates so the best context is used.
  • Hybrid (semantic + keyword) search: Combines vector similarity with keyword matching to catch exact terms/codes.
  • Metadata filtering: Restrict retrieval by attributes (doc type, recency) for precision and scoping.
  • Top-k trade-offs: Higher k improves recall but adds noise/cost; retrieve broad then re-rank.

Implementation steps:

  1. Experiment with chunk size/overlap; measure retrieval precision.
  2. Add a re-ranker over initial candidates.
  3. Combine vector + keyword (hybrid) search.
  4. Filter by metadata (type/recency).

Outcomes:

  • Higher answer relevance on jargon-heavy queries.
  • Better precision at controlled cost.
  • Scoped, current retrieval.

Stack: Vector Search, Re-ranker, Python

3. Prompt engineering & structured output

Goal: Get consistent, parseable answers (e.g., JSON) with guardrails.

Architecture & data model: A prompt template (system rules + few-shot + schema) with input/output guardrails and low temperature drives consistent structured answers.

Concepts covered:

  • Guardrails: Validate/filter inputs and outputs for safety, policy, and format.
  • Temperature control: Low temperature for factual/deterministic answers; higher for creative tasks.

Implementation steps:

  1. Design a system prompt with grounding + abstention rules.
  2. Add few-shot examples for the target format.
  3. Enforce a JSON schema for outputs.
  4. Set low temperature; add guardrails on inputs/outputs.

Outcomes:

  • Consistent, parseable responses.
  • Safer inputs/outputs.
  • Reliable integration into BI tools.

Architecture & data model: A golden dataset + LLM-as-judge scoring wired through MLflow gates deployment on metric thresholds; A/B compares prompt variants.

  • Evidence-based prompt/model choices.

Practice questions (100)

1. What is the primary benefit of Retrieval-Augmented Generation (RAG)?

  • A. It fine-tunes the base model automatically
  • B. It grounds responses in retrieved, relevant context to reduce hallucination and use current/proprietary data ✓
  • C. It removes the need for embeddings
  • D. It compresses the model weights

Explanation: RAG retrieves relevant documents and adds them to the prompt so the model answers from real, up-to-date, or proprietary content rather than only its training data — reducing hallucination without retraining the model.

2. What are embeddings used for in a RAG system?

  • A. Encrypting documents
  • B. Representing text as vectors so semantic similarity can be measured for retrieval ✓
  • C. Compressing the vector store
  • D. Formatting the final answer

Explanation: Embeddings convert text into numeric vectors where semantically similar text is close together. Retrieval embeds the query and finds the nearest document vectors (e.g., by cosine similarity) to supply as context.

3. In a RAG pipeline, why does chunk size matter?

  • A. Larger chunks are always better
  • B. It trades off context completeness against retrieval precision and token cost ✓
  • C. It only affects storage
  • D. It determines the model temperature

Explanation: Chunks that are too large add noise and cost more tokens; too small lose surrounding context. Choosing chunk size/overlap balances retrieval precision, answer completeness, and prompt token budget.

4. Which Databricks feature stores embeddings and can automatically sync from a Delta table?

  • A. Delta Live Tables
  • B. Databricks Vector Search (Delta Sync Index) ✓
  • C. Unity Catalog volumes
  • D. Auto Loader

Explanation: Databricks Vector Search indexes embeddings for similarity retrieval and offers a Delta Sync Index that keeps the index up to date as the source Delta table changes.

5. Which metric measures whether an answer is actually supported by the retrieved context?

  • A. Latency
  • B. Groundedness (faithfulness) ✓
  • C. Throughput
  • D. Token count

Explanation: Groundedness/faithfulness checks that the generated answer is backed by the retrieved context rather than fabricated. It's a core RAG-quality metric alongside answer relevance and context relevance.

6. Lowering an LLM's temperature parameter generally makes output:

  • A. More random and creative
  • B. More deterministic and focused ✓
  • C. Longer
  • D. Multilingual

Explanation: Lower temperature reduces randomness, making the model pick higher-probability tokens — more deterministic, focused answers. Higher temperature increases diversity/creativity but also the risk of drift.

7. A model returns confident but fabricated facts not present in the source documents. The best first mitigation in a RAG app is to:

  • A. Increase temperature
  • B. Improve retrieval and instruct the model to answer only from provided context (and say 'I don't know' otherwise) ✓
  • C. Remove the vector store
  • D. Switch to a smaller model

Explanation: Hallucination in RAG is often a retrieval/prompt problem: ensure relevant context is retrieved and instruct the model to ground answers strictly in that context, abstaining when it's absent. Raising temperature would worsen it.

8. What does Model Serving provide on Databricks?

  • A. A notebook scheduler
  • B. Real-time REST endpoints to serve models/LLMs for inference ✓
  • C. A vector database
  • D. A data-quality framework

Explanation: Model Serving deploys models (including LLM chains) behind scalable REST endpoints for low-latency inference, integrated with MLflow and Unity Catalog governance.

9. Which approach adds proprietary, frequently-changing knowledge to an app with the least retraining effort?

  • A. Full pre-training
  • B. Fine-tuning weekly
  • C. RAG over a maintained document store ✓
  • D. Prompt-only with no data

Explanation: RAG lets you update the knowledge base (documents/index) independently of the model, so new or changing information is available immediately without retraining or fine-tuning.

10. Few-shot prompting means:

  • A. Training the model on a few GPUs
  • B. Including a few worked examples in the prompt to guide the desired output format/behavior ✓
  • C. Limiting the response to a few tokens
  • D. Using a few retrieval chunks

Explanation: Few-shot prompting provides example input→output pairs directly in the prompt so the model infers the pattern and produces consistent, well-formatted responses — without any weight updates.

11. Which similarity metric is commonly used to compare embedding vectors in retrieval?

  • A. Manhattan only
  • B. Cosine similarity ✓
  • C. Levenshtein distance
  • D. Jaccard on characters

Explanation: Cosine similarity measures the angle between vectors, capturing semantic closeness regardless of magnitude — the standard for embedding retrieval (dot product/L2 are also used).

12. What is 'chunking' in a RAG pipeline?

  • A. Compressing the model
  • B. Splitting source documents into smaller passages before embedding ✓
  • C. Batching GPU jobs
  • D. Truncating the output

Explanation: Chunking divides documents into passages sized for embedding and retrieval, balancing enough context per chunk against precision and token cost.

13. MLflow helps in a GenAI project by:

  • A. Only storing data
  • B. Tracking experiments, logging models/prompts, and evaluating LLM outputs ✓
  • C. Serving dashboards
  • D. Replacing the vector store

Explanation: MLflow provides experiment tracking, model logging/registry, and GenAI evaluation tooling, giving reproducibility and governance across the LLM lifecycle.

14. Increasing 'top-k' in retrieval generally:

  • A. Reduces the context passed to the model
  • B. Retrieves more candidate chunks, adding context but also noise and tokens ✓
  • C. Disables grounding
  • D. Lowers latency to zero

Explanation: Higher top-k returns more chunks, improving recall of relevant context but risking irrelevant content and higher token cost. Tuning top-k trades recall against precision/cost.

15. A guardrail in an LLM application is used to:

  • A. Speed up inference
  • B. Constrain inputs/outputs for safety, policy, or format compliance ✓
  • C. Store embeddings
  • D. Compress the prompt

Explanation: Guardrails validate or filter prompts and responses — blocking unsafe content, enforcing output format, or preventing PII leakage — improving safety and reliability.

16. Which is a reason to choose a smaller/cheaper model for part of a pipeline?

  • A. It is always more accurate
  • B. Cost/latency optimization for simpler subtasks (e.g., routing, classification) ✓
  • C. It removes the need for retrieval
  • D. It guarantees no hallucination

Explanation: Right-sizing models — using a small model for routing/classification and a larger one for hard generation — controls cost and latency without sacrificing quality where it matters.

17. Context relevance (a RAG metric) measures whether:

  • A. The answer is grammatical
  • B. The retrieved context is actually relevant to the question ✓
  • C. The model is fast
  • D. The prompt is short

Explanation: Context relevance evaluates the retrieval step — did we fetch context that pertains to the query. Poor context relevance usually means chunking/embedding/retrieval needs tuning.

18. A system prompt is typically used to:

  • A. Store the vector index
  • B. Set the assistant's role, rules, and behavior for the conversation ✓
  • C. Fine-tune weights
  • D. Cache responses

Explanation: The system prompt establishes persistent instructions — persona, constraints, tone, and rules — that shape how the model responds throughout the interaction.

19. Fine-tuning differs from RAG in that fine-tuning:

  • A. Retrieves documents at query time
  • B. Updates model weights on curated data to change behavior/style ✓
  • C. Requires a vector store
  • D. Cannot change outputs

Explanation: Fine-tuning adjusts the model's weights using training examples (good for style/format/domain behavior). RAG leaves weights unchanged and instead supplies knowledge at query time — often complementary.

20. Databricks Vector Search's 'Delta Sync Index' primarily provides:

  • A. Manual re-embedding only
  • B. Automatic keeping of the index in sync with a source Delta table ✓
  • C. A chat UI
  • D. Model fine-tuning

Explanation: A Delta Sync Index automatically updates the vector index as the underlying Delta table changes, so retrieval reflects fresh data without manual re-indexing.

21. To reduce cost when the same prompts recur, a useful technique is:

  • A. Increase top-k
  • B. Response/semantic caching ✓
  • C. Disable guardrails
  • D. Raise temperature

Explanation: Caching responses to identical (or semantically similar) prompts avoids repeated model calls, cutting cost and latency for common queries.

22. Which statement about tokens is correct?

  • A. One token always equals one word
  • B. Tokens are sub-word units; cost and context limits are measured in tokens ✓
  • C. Tokens are only for images
  • D. Tokens don't affect cost

Explanation: LLMs process text as tokens (sub-word pieces). Both the context window and pricing are measured in tokens, so managing token usage controls capability and cost.

23. An evaluation using 'LLM-as-a-judge' means:

  • A. Users manually grade every answer
  • B. A capable model scores outputs against criteria (e.g., relevance, groundedness) ✓
  • C. The model trains itself
  • D. No evaluation is done

Explanation: LLM-as-a-judge uses a strong model to score responses against a rubric at scale, complementing human review and enabling automated regression testing of GenAI quality.

24. A vector database is optimized for:

  • A. Transactional row updates
  • B. Approximate nearest-neighbor search over high-dimensional embeddings ✓
  • C. Storing images only
  • D. Compiling code

Explanation: Vector stores index embeddings for fast approximate nearest-neighbor (ANN) similarity search, the retrieval backbone of RAG.

25. Chain-of-thought / step-by-step prompting tends to:

  • A. Reduce reasoning quality
  • B. Improve performance on multi-step reasoning tasks by eliciting intermediate steps ✓
  • C. Always increase hallucination
  • D. Disable retrieval

Explanation: Encouraging the model to reason step by step often improves accuracy on complex/multi-step problems, though it uses more tokens. (Some deployments hide the reasoning from users.)

26. Which is a sign that chunk size is too large?

  • A. Retrieval is precise
  • B. Retrieved chunks contain much irrelevant text, diluting the prompt and raising cost ✓
  • C. Faster embedding
  • D. Better recall always

Explanation: Overly large chunks bundle unrelated content, reducing precision and wasting tokens. Smaller, well-bounded chunks (with slight overlap) usually retrieve more targeted context.

27. Re-ranking retrieved candidates before generation is used to:

  • A. Encrypt them
  • B. Reorder results by relevance (e.g., a cross-encoder) so the best context is prioritized ✓
  • C. Reduce the vector dimension
  • D. Fine-tune the model

Explanation: A re-ranker scores initial retrieval candidates more precisely (often a cross-encoder), pushing the most relevant chunks to the top so the generator sees the best context first.

28. Model Serving endpoints on Databricks support:

  • A. Only batch scoring
  • B. Real-time inference with autoscaling and governance ✓
  • C. Only SQL
  • D. No monitoring

Explanation: Model Serving provides scalable real-time REST endpoints (with autoscaling, logging, and Unity Catalog governance) for models and LLM chains.

29. Which metric captures whether the final answer addresses the user's actual question?

  • A. Context relevance
  • B. Answer relevance ✓
  • C. Latency
  • D. Token count

Explanation: Answer relevance measures how well the response addresses the query. Context relevance evaluates retrieval; both (plus groundedness) form the core RAG triad.

30. Setting max_tokens on a response controls:

  • A. The embedding size
  • B. The maximum length of the generated output ✓
  • C. The retrieval top-k
  • D. The temperature

Explanation: max_tokens caps how many tokens the model may generate, bounding response length and cost. It doesn't affect retrieval or embeddings.

31. A hybrid search combines:

  • A. Two LLMs
  • B. Semantic (vector) search with keyword/lexical search for better recall ✓
  • C. Two vector stores only
  • D. Batch and streaming

Explanation: Hybrid search blends dense vector similarity with sparse keyword matching (e.g., BM25), improving retrieval when exact terms matter as well as semantics.

32. Which is a valid reason to fine-tune rather than rely solely on prompting/RAG?

  • A. To add fast-changing facts
  • B. To reliably enforce a specific style/format or teach a narrow behavior at scale ✓
  • C. To avoid any training data
  • D. To reduce model size automatically

Explanation: Fine-tuning is well-suited to consistent style/format or specialized behaviors. Volatile factual knowledge is better served by RAG, which updates without retraining.

33. Grounding a response strictly in retrieved context primarily reduces:

  • A. Latency
  • B. Hallucination ✓
  • C. Token cost
  • D. Embedding size

Explanation: Instructing the model to answer only from provided context (and abstain otherwise) constrains it to supported facts, reducing fabricated/hallucinated answers.

  • C. It disables the model

Explanation: Temperature 0 makes generation greedy/deterministic — best for factual, repeatable tasks. Higher temperatures add diversity useful for creative generation.

Explanation: The prompt (instructions + retrieved context + history) must fit the window. Reducing top-k, using smaller chunks, or summarizing keeps it within budget.

  • C. Fine-tune the model
  • D. Increase temperature
