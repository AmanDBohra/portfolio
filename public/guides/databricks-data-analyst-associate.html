Databricks Certified Data Analyst Associate — Study Guide

Analytics on the Lakehouse with Databricks SQL: writing queries, building visualizations, dashboards and alerts, managing data with Delta, and applying basic analytics and governance as an analyst.

~45 questions · 90 minutes · focused on Databricks SQL, visualization and analytics · passing ~70%.

What it is

The Databricks Certified Data Analyst Associate validates the ability to turn Lakehouse data into insight using Databricks SQL. It covers writing SQL queries (joins, aggregations, CTEs, window functions), building visualizations, dashboards, and alerts, doing last-mile data preparation with Delta tables and views, and applying basic analytics and Unity Catalog governance from an analyst's perspective.

It is aimed at analysts rather than engineers: the focus is querying and communicating data on the Lakehouse, using SQL warehouses, dashboards, parameters, and alerts to support decisions.

Where it's used

  • Roles: Data Analyst, BI Analyst, Reporting Analyst, Analytics Engineer working in Databricks SQL.
  • On the job: exploring data with SQL, building interactive dashboards and threshold alerts, and creating governed views/gold tables for reporting.
  • Career value: validates analytics capability on the modern Lakehouse, complementing BI tools like Power BI and Qlik.
  • For this portfolio: reinforces BI and KPI-reporting delivery, applied on a Lakehouse foundation.

In plain English

  • A SQL warehouse is the engine that runs your queries — like the horsepower of a car. Bigger warehouse = faster/more concurrent, but costs more.
  • A view is a saved question, not a saved answer — it re-asks the data every time, so it's always current. A copied table is a saved answer that can go stale.
  • An alert is a smoke detector for your data: it runs a query on a schedule and beeps (notifies) when a number crosses a line you set.
  • A dashboard parameter is a knob viewers can turn (pick a date, a region) so one dashboard answers many questions.

Exam shortcut tricks

  1. WHERE filters rows BEFORE grouping; HAVING filters groups AFTER aggregation (can use SUM/COUNT). Mixing these up is a classic trap.
  2. Window functions (ROW_NUMBER/RANK/LAG/LEAD OVER ...) rank or compare rows WITHOUT collapsing them — the go-to for 'top N per group' and 'vs previous period.'
  3. Counter/KPI visual = one headline number. Line = trend over time. Bar = compare categories. Scatter = relationship. Pick by the question.
  4. COUNT(*) counts all rows; COUNT(col) skips nulls; COUNT(DISTINCT col) = unique. Read carefully which one the question wants.
  5. Guard division with NULLIF (x / NULLIF(y,0)) to avoid divide-by-zero.
  6. Serverless SQL warehouse = starts fast, autoscales — the answer for 'reduce wait time / idle cost.'
  7. Alerts = notify on a condition; scheduled refresh = keep data current. Don't confuse the two.

Study notes

Databricks SQL & warehouses

  • A SQL warehouse (formerly SQL endpoint) is the compute that runs Databricks SQL queries; sizing affects speed and concurrency.
  • Serverless SQL warehouses start quickly and autoscale.
  • Query results can be cached to speed up repeated runs.

Visualizations & dashboards

  • Each query can have one or more visualizations (bar, line, pie, counter, table, etc.).
  • Dashboards assemble visualizations; query parameters make them interactive.
  • Dashboards can be scheduled to refresh and be shared with viewers.

Alerts

  • Alerts run a query on a schedule and evaluate a condition on a column value; when met, they notify via destinations (email, etc.).
  • Useful for threshold monitoring (e.g., daily errors > N).

Analyst data management

  • Analysts often do 'last-mile' transformations creating views or gold tables for reporting.
  • Delta tables give reliable, versioned data; use CTAS or views to shape data for dashboards.

3. Window-function analytics: trends & rankings

Goal: Show month-over-month change and top-N distributors without collapsing rows.

Architecture & data model: Gold fact queried with window functions to produce MoM change, running totals, per-region top-N, and % of total — surfaced in a dashboard.

Concepts covered:

  • Window functions (ROW_NUMBER, RANK, LAG): Rank rows and compare to prior rows without collapsing them.
  • Running totals (SUM OVER): Cumulative sums over an ordered window for trends.
  • % of total: value / SUM(value) OVER () gives each row's share of the whole.
  • date_trunc for periods: Normalizes timestamps to month/week for clean grouping.
  • Top-N per group: ROW_NUMBER partitioned by group, filtered to rn<=N.

Implementation steps:

  1. Group by month via date_trunc.
  2. Compute MoM change with LAG over an ordered window.
  3. Rank distributors per region with ROW_NUMBER; keep rn<=5.
  4. Add % of total via SUM(x) OVER ().

Outcomes:

  • Trend, ranking, and contribution analytics.
  • No self-joins needed for period comparisons.
  • Clear top-performer views.

5. Governed analyst data layer

Goal: Create reusable, secured views and gold tables for a reporting team.

Architecture & data model: Governed views/gold tables in Unity Catalog form one source of truth; analysts query via serverless warehouses with result caching.

  • Reduced metric drift across reports.

Practice questions (100)

1. What is a SQL warehouse in Databricks SQL?

  • A. A storage location for Delta files
  • B. The compute resource that executes Databricks SQL queries ✓
  • C. A dashboard template
  • D. A Unity Catalog metastore

Explanation: A SQL warehouse (previously 'SQL endpoint') is the compute cluster that runs Databricks SQL queries. Its size and type (including serverless) determine query performance and concurrency.

2. How do you make a Databricks SQL dashboard interactive so viewers can change a filter value?

  • A. Add a query parameter ✓
  • B. Duplicate the dashboard per value
  • C. Use VACUUM
  • D. Enable Photon

Explanation: Query parameters expose inputs (dropdowns, date pickers, text) that viewers can change, and the dashboard re-runs with the new value — the standard way to add interactivity.

3. What does a Databricks SQL alert do?

  • A. Automatically fixes failed queries
  • B. Runs a query on a schedule and notifies when a condition on the result is met ✓
  • C. Compacts small files
  • D. Grants table permissions

Explanation: An alert periodically runs a query and checks a condition against a returned value (e.g., count > threshold). When the condition is satisfied it sends notifications to configured destinations.

4. Which visualization is best for showing a single key metric prominently?

  • A. Counter ✓
  • B. Scatter plot
  • C. Box plot
  • D. Heatmap

Explanation: A Counter visualization displays a single value (optionally vs a target) in large type — ideal for headline KPIs. Scatter/box/heatmap are for distributions and relationships.

5. An analyst needs a reusable, always-current shaping of data for several dashboards without copying data. What is the best choice?

  • A. A CSV export
  • B. A view ✓
  • C. A temp view in one notebook
  • D. A screenshot

Explanation: A view stores the query logic and always reflects the latest underlying data, and it's reusable across dashboards. A temp view is session-scoped (not shareable), and CSV exports go stale immediately.

6. Which benefit does query result caching provide?

  • A. It rewrites the SQL for you
  • B. Repeated identical queries return faster without re-executing on the warehouse ✓
  • C. It encrypts the results
  • D. It creates a Delta table automatically

Explanation: Result caching returns previously computed results for identical queries, reducing latency and warehouse load. It's invalidated when underlying data changes.

7. In the three-level namespace, how does an analyst fully qualify a table?

  • A. schema.table
  • B. catalog.schema.table ✓
  • C. warehouse.table
  • D. table only

Explanation: Databricks SQL with Unity Catalog uses catalog.schema.table. Fully qualifying avoids ambiguity when multiple catalogs/schemas contain similarly named tables.

8. Which SQL construct improves readability by naming a subquery you reference later in the same statement?

  • A. A CTE (WITH clause) ✓
  • B. A GRANT
  • C. A window function
  • D. A VACUUM

Explanation: A Common Table Expression (WITH name AS (...)) defines a named, reusable result set within a query, improving readability and letting you reference it multiple times.

9. What is the most appropriate chart to show a trend over time?

  • A. Pie chart
  • B. Line chart ✓
  • C. Counter
  • D. Table

Explanation: A line chart shows how a measure changes across a continuous dimension like time, making trends and seasonality easy to read. Pie charts show part-to-whole at one point, not trends.

10. Why might an analyst prefer a serverless SQL warehouse?

  • A. It stores more data
  • B. It starts quickly and autoscales, reducing idle cost and wait time ✓
  • C. It disables governance
  • D. It guarantees exactly-once streaming

Explanation: Serverless SQL warehouses spin up almost instantly and scale with demand, so analysts avoid long cluster start times and pay less for idle compute — ideal for interactive, bursty query workloads.

11. Which SQL clause restricts grouped results based on an aggregate condition?

  • A. WHERE
  • B. HAVING ✓
  • C. LIMIT
  • D. ORDER BY

Explanation: HAVING filters groups after GROUP BY using aggregate conditions (e.g., HAVING SUM(sales) > 1000). WHERE filters rows before aggregation and cannot reference aggregates.

12. A window function like ROW_NUMBER() OVER (PARTITION BY region ORDER BY sales DESC) is used to:

  • A. Delete rows
  • B. Rank rows within partitions without collapsing them ✓
  • C. Join two tables
  • D. Create a dashboard

Explanation: Window functions compute values across a set of rows (a window) while keeping every row — ideal for ranking, running totals, and top-N-per-group without a GROUP BY collapse.

13. What is the benefit of the Databricks SQL query history?

  • A. It stores dashboards
  • B. It lets you review past queries, their runtime, and troubleshoot performance ✓
  • C. It encrypts data
  • D. It replaces Unity Catalog

Explanation: Query history records executed queries with duration and status, helping analysts audit usage and identify slow queries to optimize.

14. Which visualization best shows the relationship between two numeric measures?

  • A. Scatter plot ✓
  • B. Counter
  • C. Pivot table
  • D. Funnel

Explanation: A scatter plot maps two numeric variables on x and y axes, revealing correlation, clusters, and outliers — the right choice for relationship analysis.

15. In Databricks SQL, a parameter marker in a query (e.g., :start_date) enables:

  • A. Encryption
  • B. Reusable queries/dashboards where users supply a value at runtime ✓
  • C. Automatic joins
  • D. Row-level security

Explanation: Query parameters let a single query accept runtime inputs, powering interactive dashboards and avoiding hard-coded values.

16. Which is TRUE about a view versus a table for an analyst?

  • A. A view stores its own copy of the data
  • B. A view stores only the query; it always reflects current underlying data ✓
  • C. Tables can't be queried
  • D. Views are faster in every case

Explanation: A view is a saved query with no data of its own, so it always returns current results from its base tables. It's ideal for consistent, reusable logic; materialized copies would go stale.

17. A COUNT(DISTINCT customer_id) measures:

  • A. Total rows
  • B. Number of unique customers ✓
  • C. Sum of ids
  • D. Average id

Explanation: COUNT(DISTINCT col) counts unique non-null values — here, distinct customers — as opposed to COUNT(*) which counts all rows.

18. Which chart is best to show composition of a whole at a single point in time (few categories)?

  • A. Line chart
  • B. Pie/donut chart ✓
  • C. Scatter plot
  • D. Histogram

Explanation: A pie/donut shows part-to-whole for a small number of categories at one point in time. With many categories a bar chart is clearer; for trends over time use a line chart.

19. To schedule a dashboard to refresh every morning, an analyst configures:

  • A. A VACUUM job
  • B. A dashboard/query refresh schedule ✓
  • C. A synthetic key
  • D. A broadcast join

Explanation: Databricks SQL dashboards and their queries can be set on a refresh schedule so data is up to date when viewers open them, optionally notifying subscribers.

20. A histogram is most appropriate for showing:

  • A. A trend over time
  • B. The distribution of a single numeric variable across bins ✓
  • C. Part-to-whole
  • D. Correlation of two variables

Explanation: A histogram buckets a numeric variable into ranges and shows frequency per bucket, revealing the shape of a distribution (skew, spread, modes).

21. Which SQL construct lets you categorize rows into labels inline (e.g., 'High'/'Low')?

  • A. CASE WHEN ... THEN ... END ✓
  • B. GROUP BY only
  • C. VACUUM
  • D. OPTIMIZE

Explanation: A CASE expression returns conditional values row by row, useful for bucketing/labeling (e.g., CASE WHEN sales>1000 THEN 'High' ELSE 'Low' END).

22. Photon in Databricks SQL primarily provides:

  • A. A visualization library
  • B. A vectorized query engine that speeds up SQL/DataFrame workloads ✓
  • C. A governance tool
  • D. A scheduler

Explanation: Photon is a native vectorized execution engine that accelerates SQL and DataFrame queries on Databricks, improving performance and cost efficiency for analytics.

23. Which JOIN returns all rows from both tables, matching where possible and null elsewhere?

  • A. INNER JOIN
  • B. LEFT JOIN
  • C. FULL OUTER JOIN ✓
  • D. CROSS JOIN

Explanation: A FULL OUTER JOIN returns matched rows plus unmatched rows from both sides (with nulls for missing columns). INNER returns only matches; CROSS returns the Cartesian product.

24. Which clause limits the number of rows returned by a query?

  • A. TOP
  • B. LIMIT ✓
  • C. FETCH ONLY
  • D. TRUNCATE

Explanation: LIMIT n restricts output to n rows in Databricks SQL (Spark SQL). It's often combined with ORDER BY for top-N results.

25. A LEFT JOIN returns:

  • A. Only matching rows
  • B. All rows from the left table plus matches (nulls where no match) ✓
  • C. The Cartesian product
  • D. Only right-table rows

Explanation: A LEFT (outer) JOIN keeps every row from the left table, filling right-side columns with null where there's no match — useful to retain all base records.

26. Which visualization is best for comparing a metric across a small set of categories?

  • A. Bar chart ✓
  • B. Line chart
  • C. Scatter plot
  • D. Map

Explanation: A bar chart makes category comparisons easy via bar length. Lines imply trend/continuity; scatter shows relationships; maps show geography.

27. GROUP BY is required when a query:

  • A. Selects only raw columns
  • B. Mixes aggregate functions with non-aggregated columns ✓
  • C. Uses LIMIT
  • D. Has a WHERE clause

Explanation: When you aggregate (SUM, COUNT) alongside non-aggregated columns, those columns must appear in GROUP BY so the engine knows how to group rows before aggregating.

28. A dashboard parameter with a query-based dropdown:

  • A. Hard-codes values
  • B. Populates its choices from a query, keeping options in sync with data ✓
  • C. Disables refresh
  • D. Encrypts the dashboard

Explanation: Query-based dropdown parameters derive their selectable values from a query, so the filter options stay current as the underlying data changes.

29. The COALESCE(a, b) function returns:

  • A. The larger of a and b
  • B. The first non-null value among its arguments ✓
  • C. Always a
  • D. Null if either is null

Explanation: COALESCE returns the first non-null argument, commonly used to substitute defaults for missing values (e.g., COALESCE(region,'Unknown')).

30. Which is a valid reason to use a CTE over a nested subquery?

  • A. It is always faster
  • B. Readability and the ability to reference the same intermediate result multiple times ✓
  • C. It encrypts data
  • D. It creates a table

Explanation: CTEs (WITH) name intermediate results, improving readability and allowing reuse within the statement — clearer than deeply nested subqueries.

31. An alert's 'trigger condition' is evaluated against:

  • A. The dashboard layout
  • B. A value in the alert query's result (e.g., a column exceeding a threshold) ✓
  • C. The cluster size
  • D. The user's role

Explanation: Alerts run a query and compare a chosen result value to a condition/threshold; when satisfied, notifications fire to the configured destinations.

32. To show percentage contribution of each category to a total in a table, you can use:

  • A. A window function like SUM(x) OVER () ✓
  • B. LIMIT
  • C. TRUNCATE
  • D. VACUUM

Explanation: Dividing each row's value by SUM(x) OVER () (the grand total window) yields each category's share of the total without collapsing rows.

33. Which is TRUE about a materialized result vs a view for a heavy query?

  • A. A view recomputes each time; a materialized table stores results for fast reuse but can go stale ✓
  • B. They are identical
  • C. Views are always slower to write
  • D. Materialized results can't be refreshed

Explanation: A view re-runs its query on each access (always current). A materialized/stored table caches results for speed but needs refreshing to stay current — a freshness vs performance trade-off.

34. Which function extracts the year from a date column?

  • A. YEAR(date_col) ✓

  • D. TRUNC()

Explanation: YEAR(date_col) returns the year component. Related functions include MONTH(), DAYOFWEEK(), and date_trunc('month', col) for period grouping.

Explanation: AVG(col) averages only non-null values (denominator excludes nulls). SUM/COUNT(*) would divide by all rows including nulls, giving a different result.

43. A box plot is best for showing:

45. NULLIF(a, b) returns:

  • A. a if a=b
  • B. NULL if a=b, otherwise a ✓
  • C. b always
  • D. 0

Explanation: NULLIF returns NULL when the two arguments are equal (else the first) — handy to avoid divide-by-zero by turning 0 into NULL in a denominator.

46. Which chart shows geographic distribution of a measure?

  • B. The median (50th percentile) ✓
  • C. The max

Explanation: PERCENTILE_CONT(0.5) returns the median via continuous interpolation. Percentiles summarize distributions better than the mean when data is skewed.

55. Which is the benefit of parameterizing a dashboard date range?

56. A heatmap (matrix with color) is best for:

  • A. Showing intensity across two categorical dimensions ✓
  • B. A single value
  • C. A trend line
  • D. Part-to-whole

Explanation: Heatmaps encode a measure as color across a grid of two dimensions (e.g., day × hour), quickly revealing hotspots/patterns.

57. COUNT(*) vs COUNT(column) differ in that COUNT(column):

  • A. Counts all rows
  • B. Counts only rows where the column is non-null ✓
  • C. Counts distinct values
  • D. Is invalid

Explanation: COUNT(*) counts every row; COUNT(column) ignores nulls in that column. Use COUNT(DISTINCT column) for unique values.

58. Which is a valid way to share a curated dataset for others to build reports on?

Explanation: Publishing a governed table/view and granting access lets multiple analysts build on a single, consistent, secured source of truth.

59. To find the top category per region, you would use:

  • C. LIMIT 1 on the whole table
  • D. DISTINCT

Explanation: Ranking within each region via ROW_NUMBER() OVER (PARTITION BY region ORDER BY measure DESC) and keeping rn=1 returns the top item per region — a classic top-N-per-group pattern.

60. Which chart is misleading for comparing many categories precisely?

  • A. Bar chart
  • B. Pie chart with many slices ✓
  • C. Table
  • D. Column chart

Explanation: Pie charts with many slices make precise comparisons hard (angles/areas are hard to judge). Bars/columns or a sorted table are clearer for many categories.

61. A view referencing another view is:

  • A. Not allowed
  • B. Allowed (nested views) but can affect performance/maintainability ✓
  • C. Always faster
  • D. Encrypted

Explanation: Views can be layered, which aids modularity but deep nesting can hurt performance and make debugging harder — balance reuse with clarity.

62. Which function returns the day name from a date?

  • B. YEAR()
  • C. ROUND()
  • D. TRIM()

Explanation: date_format(date, 'EEEE') returns the full weekday name; format patterns control the output (e.g., 'MMM' for short month).

63. Which is TRUE about UNION vs UNION ALL?

  • A. They are identical
  • B. UNION removes duplicates; UNION ALL keeps all rows (faster) ✓
  • C. UNION ALL removes duplicates
  • D. Both sort the result

Explanation: UNION deduplicates the combined rows (extra work); UNION ALL simply appends all rows and is faster when duplicates are acceptable/impossible.

64. A correlated subquery differs from a regular subquery in that it:

  • A. Runs once
  • B. References the outer query and is evaluated per outer row ✓
  • C. Cannot use WHERE
  • D. Is always faster

Explanation: A correlated subquery depends on the outer row (e.g., WHERE x > (SELECT AVG ... WHERE dept=outer.dept)), evaluated per row — powerful but potentially costly.

65. Which visualization is best for showing composition change over time as proportions?

  • B. Scatter
  • C. Gauge
  • D. Card

Explanation: A 100% stacked chart normalizes each period to 100%, showing how category shares shift over time regardless of total magnitude.

66. Which is a reason to use DECIMAL over FLOAT for currency?

  • B. DECIMAL avoids floating-point rounding errors for money ✓
  • C. DECIMAL is always faster
  • D. They are the same

Explanation: Money needs exact decimal arithmetic; FLOAT/DOUBLE introduce binary rounding errors. DECIMAL(precision, scale) stores exact values.

67. LEAD(measure) OVER (ORDER BY date) returns:

Explanation: LEAD looks ahead to a following row (LAG looks back), enabling next-period comparisons within an ordered window.

  • C. Add more parameters only
  • D. Disable caching

Explanation: Pre-aggregating data and keeping pages focused reduces per-visual query cost and rendering time, improving responsiveness.

69. Which function trims whitespace from a string?

  • A. TRIM() ✓
  • B. ROUND()
  • C. YEAR()
  • D. ABS()

Explanation: TRIM() removes leading/trailing spaces; LTRIM/RTRIM trim one side. Useful for cleaning messy text keys before joins/grouping.

70. A slowly loading query filters on a non-indexed/large scan. A practical improvement is to:

  • A. Select more columns
  • B. Filter on partition/clustered columns and reduce selected columns ✓
  • C. Remove WHERE
  • D. Use SELECT *

Explanation: Filtering on partition/ZORDER columns enables data-skipping, and selecting fewer columns reduces I/O — both speed up queries on large tables.

71. Which is the safe pattern for a percentage-of-total in SQL?

  • B. value / 0
  • C. value * 100 only
  • D. COUNT(*)

Explanation: Dividing each row's value by the windowed grand total SUM(value) OVER () yields its share without collapsing rows.

72. A gauge/KPI card is inappropriate when you need to:

  • A. Show one headline number

  • D. Display a single ratio

Explanation: Single-value visuals can't compare many categories; a bar chart or table is the right tool for multi-category comparison.

73. Which is TRUE about scheduled alerts vs scheduled dashboard refresh?

  • C. Alerts render visuals

Explanation: A refresh keeps data current on a schedule; an alert evaluates a condition on results and notifies — complementary features.

74. To combine first and last name into one column, use:

75. Which chart best shows correlation and clustering of two numeric measures?

Explanation: Scatter plots reveal relationships, clusters, and outliers between two numeric variables — unlike pie/KPI/funnel which serve other purposes.

76. Which is TRUE about EXCEPT between two queries?
